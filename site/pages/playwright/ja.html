Playwright のテストで遅いネットワークとパケットロスを再現

Playwright はページをオフラインにしたり、DevTools 経由で Chromium を遅くしたりできます。npm の beannetworktester パッケージは、代わりにブラウザーの下で本物のネットワークを遅くします。テストが通信するサーバーに対して、遅延、パケットロス、速度制限、完全な切断を加えます。Chromium、Firefox、WebKit は WebSocket も含めて同じように遅くなります。パッケージには Bean Network Tester のプログラムが入っており、テストの間だけ Windows と Linux で実行します。1.1.0 以降の安定版リリースごとに公開されます。

インストール

npm install -D @playwright/test beannetworktester
npx playwright install chromium

Windows x64 または Linux x64（glibc 2.39 以降、たとえば Ubuntu 24.04）と Node 20 以降が必要です。npm はお使いのシステム向けのプログラムをオプションの依存関係としてインストールするので、オプションの依存関係を除外しないでください。

ネットワークを変えるには、Windows では管理者権限が必要です。ターミナルを「管理者として実行」で開いてください。Linux では root か、パスワードなしで sudo を実行できるユーザーが必要で、その場合 sudo で動くのはプログラムだけです。GitHub がホストする Windows ランナーは昇格した権限で動き、Ubuntu ランナーは sudo を許可しているので、ワークフローに追加の手順は要りません。

遅いネットワークでのテスト

これを tests/slow.spec.js として保存し、npx playwright test を実行します。

import http from 'node:http';
import { test, expect } from 'beannetworktester/playwright';

let server;
test.beforeAll(async () => {
  server = http.createServer((request, response) => response.end('<h1>Hello</h1>'));
  await new Promise((done) => server.listen(8000, done));
});
test.afterAll(() => server.close());

test('a page takes longer on a slow network', async ({ page, badNetwork }) => {
  await badNetwork({ server: 'http://localhost:8000', latency: 500 });
  const started = Date.now();
  await page.goto('http://localhost:8000');
  await expect(page.locator('h1')).toHaveText('Hello');
  expect(Date.now() - started).toBeGreaterThanOrEqual(500);
});

テストが通るのは、ページが本当に遅れて届くからです。そのサーバーとの間のすべてのパケットが 500 ms 待ちます。テストが終わるとネットワークは元に戻ります。Windows で latency: 200 にして測定すると、対象のサーバーへのリクエストは 0.8 ms から 404 ms になり（リクエストと応答の両方が待つため）、Chromium のページは 13 ms から 416 ms になりました。対象外の別のローカルサーバーは、その間 1.6 ms で応答していました。

権限がすぐに使えない場合は、badNetwork({ simulate: true, latency: 500 }) を使います。作り物の通信でプログラムを動かし、ネットワークには何も変更を加えません。パッケージが正しく入っているかの確認用で、何も遅くしません。

badNetwork フィクスチャ

test と expect を @playwright/test ではなく beannetworktester/playwright からインポートします。badNetwork を呼ぶとセッションが始まり、ネットワークが遅くなった時点で完了します。セッションはテストが成功しても失敗してもクラッシュしても、テストの終わりに止まり、プログラムのサマリーが bad-network としてテストのレポートに添付されます。途中で条件を変えるには、次のセッションを始める前に最初のセッションを止めます。

test('the app recovers when the API comes back', async ({ page, badNetwork }) => {
  const outage = await badNetwork({ server: 'http://localhost:8000', loss: 100 });
  await page.goto('http://localhost:3000');
  await expect(page.getByText('Offline')).toBeVisible();
  await outage.stop();
  await expect(page.getByText('Offline')).toBeHidden();
});

Playwright Test の外では、require('beannetworktester') の badNetwork で同じセッションを始められます。const session = await badNetwork({ ... }) と書き、await session.stop() で終了してサマリーを受け取ります。

セッションの対象

どのセッションも何かを対象にし、変わるのはその通信だけです。対象のないセッションはマシンのすべての接続を、テストランナー自身の接続まで遅くしてしまうため、開始しません。

  • server: 'http://localhost:3000' は、そのアドレスとポートへのすべての接続を遅くします。ブラウザーからでも、API サーバーからでも、ほかのどのプログラムからでもです。'db.local:5432' やサーバーのリストも使えます。これが第一の選択肢で、Windows でも Linux でも正確です。
  • process: 'self' は、テストワーカーと、それが起動したすべてのプログラム（ブラウザーなど）を遅くします。テスト自身が起動したプロセスは、その ChildProcess を渡します。
  • dstPort、dstIp、target はプログラム自身の対象で、その構文で書きます。既知のポートやアドレスにある API 向けです。一致するものすべてに届きます。dstPort: 443 はエディターの通信も含むマシンのすべての HTTPS 接続、target: 'node' は名前に「node」を含むすべてのプログラムです。

一緒に指定した対象は互いを絞り込みます。server と process: 'self' を合わせると、このワーカーからそのサーバーへの接続だけが遅くなります。Linux では、process と target が新しい接続に効くのは、開いてから最大で約 0.2 秒後です。最初のリクエストが大事なときはサーバーを対象にしてください。

セッションでできること

各設定はプログラムのコマンドラインオプションのひとつです。latency: 300 はすべてのパケットに 300 ms を加え、jitter: 100 はその遅延を揺らし、loss: 5 はパケットの 5 % を落とし、down と up は速度を KB/s で制限し、loss: 100 はサーバーを切り離します。preset: 'presets.3g' は回線プロファイル一式で、seed: 42 は毎回同じランダムな選択をします。シナリオは秒ごとに条件を変えます：scenario: 'scenarios/cafe-wifi.json'。シナリオのステップはネットワークの振る舞いを変えられますが、セッションの対象は変えられません。

並列ワーカーと上限

  • 一度にひとつ。同じ通信に 2 つのセッションをかけると効果が重なるため、並列ワーカーは順番待ちをし、それぞれ最大 wait 秒（指定しなければ 600）待ちます。同じテスト内の 2 つ目のセッションはすぐに拒否されます。
  • テストとともに終わります。テストワーカーが落ちると、プログラムはそれに気づいてすぐ止まります。duration（指定しなければ 300 秒）は、どんな場合でもセッションが動ける最長時間です。
  • 何もしなかったときは知らせます。対象に何も届かず、何も遅くしなかったセッションは BadNetworkWarning で終わります。よくある原因は、アプリが対象とは別のアドレス、たとえばコンテナと通信していることです。
  • macOS。プログラムは Windows と Linux で動きます。Mac では、Linux x86_64 のコンテナや仮想マシン、または CI ランナーでテストを実行してください。
