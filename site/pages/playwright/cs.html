Simulace pomalé sítě a ztráty paketů v testech Playwright

Playwright umí stránku odpojit od sítě a zpomalit Chromium přes DevTools. Balíček beannetworktester z npm místo toho zpomalí skutečnou síť, pod prohlížečem: latenci, ztrátu paketů, omezení rychlosti nebo úplný výpadek, pro server, se kterým váš test mluví. Chromium, Firefox i WebKit se zpomalí stejně, včetně WebSocketů. Balíček obsahuje program Bean Network Tester a spouští ho po dobu testu, ve Windows i v Linuxu. Vychází s každou stabilní verzí od 1.1.0.

Instalace

npm install -D @playwright/test beannetworktester
npx playwright install chromium

Potřebuje Windows x64 nebo Linux x64 (glibc 2.39 nebo novější, například Ubuntu 24.04) a Node 20 nebo novější. npm instaluje program pro váš systém jako volitelnou závislost, takže volitelné závislosti nevynechávejte.

Změna sítě potřebuje ve Windows práva správce: otevřete terminál přes „Spustit jako správce“. V Linuxu potřebuje root nebo uživatele, který smí spouštět sudo bez hesla, a pak pod sudo běží jen program. Hostované runnery GitHubu s Windows běží se zvýšenými právy a ty s Ubuntu povolují sudo, takže workflow nepotřebuje žádný krok navíc.

Test na pomalé síti

Uložte to jako tests/slow.spec.js a spusťte npx playwright test:

import http from 'node:http';
import { test, expect } from 'beannetworktester/playwright';

let server;
test.beforeAll(async () => {
  server = http.createServer((request, response) => response.end('<h1>Hello</h1>'));
  await new Promise((done) => server.listen(8000, done));
});
test.afterAll(() => server.close());

test('a page takes longer on a slow network', async ({ page, badNetwork }) => {
  await badNetwork({ server: 'http://localhost:8000', latency: 500 });
  const started = Date.now();
  await page.goto('http://localhost:8000');
  await expect(page.locator('h1')).toHaveText('Hello');
  expect(Date.now() - started).toBeGreaterThanOrEqual(500);
});

Test projde, protože stránka opravdu přijde později: každý paket k tomu serveru a od něj čeká 500 ms. Po skončení testu je síť zase normální. Změřeno ve Windows s latency: 200: požadavek na server v cíli trval místo 0,8 ms 404 ms, protože čeká požadavek i odpověď, a stránka v Chromiu místo 13 ms 416 ms. Jiný místní server, mimo cíl, mezitím odpovídal za 1,6 ms.

Nemáte práva po ruce? badNetwork({ simulate: true, latency: 500 }) spustí program na vymyšleném provozu a na síti nic nezmění. Ověří, že je balíček správně nainstalovaný, a nic nezpomalí.

Fixture badNetwork

Importujte test a expect z beannetworktester/playwright místo z @playwright/test. badNetwork spustí sezení, když ho zavoláte, a skončí čekání, jakmile je síť pomalá. Sezení skončí s koncem testu, ať prošel, selhal, nebo spadl, a souhrn programu se připojí ke zprávě testu jako bad-network. Chcete-li uprostřed testu změnit podmínky, zastavte první sezení dřív, než spustíte další:

test('the app recovers when the API comes back', async ({ page, badNetwork }) => {
  const outage = await badNetwork({ server: 'http://localhost:8000', loss: 100 });
  await page.goto('http://localhost:3000');
  await expect(page.getByText('Offline')).toBeVisible();
  await outage.stop();
  await expect(page.getByText('Offline')).toBeHidden();
});

Mimo Playwright Test spustí stejné sezení badNetwork z require('beannetworktester'): const session = await badNetwork({ ... }), a await session.stop() ho ukončí a vrátí souhrn.

Na co sezení míří

Každé sezení na něco míří a mění se jen tento provoz. Sezení bez cíle by zpomalilo každé spojení počítače, i spojení samotného spouštěče testů, a proto se vůbec nespustí.

  • server: 'http://localhost:3000' zpomalí každé spojení s touto adresou a portem, z prohlížeče, z vašeho API serveru nebo z jakéhokoli jiného programu. Funguje i 'db.local:5432' a seznam serverů. To je první volba a ve Windows i v Linuxu je přesná.
  • process: 'self' zpomalí testovací worker a každý program, který spustil, například jeho prohlížeč. Proces, který spustil sám test, předáte jako jeho ChildProcess.
  • dstPort, dstIp a target jsou vlastní cíle programu, zapsané v jeho syntaxi, pro API na známém portu nebo adrese. Zasáhnou všechno, co odpovídá: dstPort: 443 je každé spojení HTTPS počítače, i spojení vašeho editoru, a target: 'node' každý program s „node“ v názvu.

Cíle zadané spolu se navzájem zužují: server s process: 'self' zpomalí jen spojení tohoto workeru s tím serverem. V Linuxu process a target zasáhnou nové spojení až asi 0,2 sekundy po jeho otevření, takže miřte na server, když záleží na prvním požadavku.

Co sezení umí

Každé nastavení je jedna z voleb příkazového řádku programu. latency: 300 přidá každému paketu 300 ms, jitter: 100 tuto prodlevu mění, loss: 5 zahodí 5 % paketů, down a up omezí rychlost v KB/s a loss: 100 server odřízne. preset: 'presets.3g' je celý profil linky a seed: 42 udělá při každém běhu stejné náhodné volby. Scénář mění podmínky, jak běží sekundy: scenario: 'scenarios/cafe-wifi.json'. Krok scénáře smí změnit, jak se síť chová, ale ne to, na co sezení míří.

Paralelní workery a meze

  • Jedno po druhém. Dvě sezení na stejném provozu by se sčítala, takže paralelní workery se střídají a každý čeká až wait sekund (600, pokud nezadáte jinak). Druhé sezení ve stejném testu je hned odmítnuto.
  • Končí s testem. Když testovací worker zanikne, program to pozná a hned se zastaví. duration (300 sekund, pokud nezadáte jinak) je v každém případě nejdelší doba sezení.
  • Řekne, když nic neudělalo. Sezení, které nic nezpomalilo, protože do jeho cíle nic nedorazilo, skončí varováním BadNetworkWarning. Obvykle aplikace mluví s jinou adresou, než je cíl, například s kontejnerem.
  • macOS. Program běží ve Windows a v Linuxu. Na Macu spusťte testy v kontejneru nebo virtuálním počítači s Linuxem x86_64, nebo na runneru CI.
