Повільна мережа і втрата пакетів у тестах Playwright

Playwright уміє відключити сторінку від мережі та сповільнити Chromium через DevTools. Пакет beannetworktester з npm натомість сповільнює справжню мережу, під браузером: затримка, втрата пакетів, обмеження швидкості або повний обрив, для сервера, з яким говорить ваш тест. Chromium, Firefox і WebKit сповільнюються однаково, разом із WebSocket. Пакет містить програму Bean Network Tester і запускає її на час тесту, у Windows і Linux. Він виходить з кожним стабільним випуском, починаючи з 1.1.0.

Встановлення

npm install -D @playwright/test beannetworktester
npx playwright install chromium

Потрібні Windows x64 або Linux x64 (glibc 2.39 або новіша, наприклад Ubuntu 24.04) і Node 20 або новіший. npm встановлює програму для вашої системи як необов'язкову залежність, тож не вимикайте необов'язкові залежності.

Щоб змінювати мережу, у Windows потрібні права адміністратора: відкрийте термінал через «Запуск від імені адміністратора». У Linux потрібен root або користувач, якому дозволено sudo без пароля, і тоді під sudo працює лише програма. Розміщені ранери GitHub з Windows працюють із підвищеними правами, а ранери з Ubuntu дозволяють sudo, тож workflow не потребує додаткового кроку.

Тест на повільній мережі

Збережіть це як tests/slow.spec.js і запустіть npx playwright test:

import http from 'node:http';
import { test, expect } from 'beannetworktester/playwright';

let server;
test.beforeAll(async () => {
  server = http.createServer((request, response) => response.end('<h1>Hello</h1>'));
  await new Promise((done) => server.listen(8000, done));
});
test.afterAll(() => server.close());

test('a page takes longer on a slow network', async ({ page, badNetwork }) => {
  await badNetwork({ server: 'http://localhost:8000', latency: 500 });
  const started = Date.now();
  await page.goto('http://localhost:8000');
  await expect(page.locator('h1')).toHaveText('Hello');
  expect(Date.now() - started).toBeGreaterThanOrEqual(500);
});

Тест проходить, бо сторінка справді приходить пізніше: кожен пакет до цього сервера й від нього чекає 500 мс. Коли тест закінчується, мережа знову працює як звичайно. Виміряно у Windows з latency: 200: запит до сервера в цілі зріс з 0,8 мс до 404 мс, бо чекають і запит, і відповідь, а сторінка в Chromium з 13 мс до 416 мс. Інший локальний сервер, поза ціллю, відповідав тим часом за 1,6 мс.

Прав під рукою немає? badNetwork({ simulate: true, latency: 500 }) запускає програму на вигаданому трафіку й нічого не змінює в мережі. Це перевіряє, що пакет установлено правильно, і нічого не сповільнює.

Фікстура badNetwork

Імпортуйте test і expect з beannetworktester/playwright замість @playwright/test. badNetwork починає сесію, коли ви її викликаєте, і завершує очікування, щойно мережа стала повільною. Сесія зупиняється разом із кінцем тесту, чи він пройшов, чи впав, чи аварійно завершився, а підсумок програми прикріплюється до звіту тесту як bad-network. Щоб змінити умови посеред тесту, зупиніть першу сесію, перш ніж починати наступну:

test('the app recovers when the API comes back', async ({ page, badNetwork }) => {
  const outage = await badNetwork({ server: 'http://localhost:8000', loss: 100 });
  await page.goto('http://localhost:3000');
  await expect(page.getByText('Offline')).toBeVisible();
  await outage.stop();
  await expect(page.getByText('Offline')).toBeHidden();
});

Поза Playwright Test ту саму сесію починає badNetwork з require('beannetworktester'): const session = await badNetwork({ ... }), а await session.stop() завершує її і повертає підсумок.

На що націлена сесія

Кожна сесія на щось націлена, і змінюється лише цей трафік. Сесія без цілі сповільнила б кожне з'єднання машини, зокрема з'єднання самого запускача тестів, тому вона не запускається.

  • server: 'http://localhost:3000' сповільнює кожне з'єднання з цією адресою та портом, з браузера, з вашого API-сервера чи з будь-якої іншої програми. Підходять і 'db.local:5432', і список серверів. Це перший вибір, і він точний у Windows і Linux.
  • process: 'self' сповільнює тестовий воркер і кожну програму, яку він запустив, наприклад його браузер. Процес, який запустив сам тест, передається як його ChildProcess.
  • dstPort, dstIp і target це власні цілі програми, записані в її синтаксисі, для API на відомому порту чи адресі. Вони дістають усе, що підходить: dstPort: 443 це кожне HTTPS-з'єднання машини, зокрема з'єднання вашого редактора, а target: 'node' кожна програма з «node» в назві.

Цілі, задані разом, звужують одна одну: server з process: 'self' сповільнює лише з'єднання цього воркера з цим сервером. У Linux process і target починають діяти на нове з'єднання із запізненням приблизно до 0,2 секунди після його відкриття, тож цільтеся в сервер, коли важливий перший запит.

Що вміє сесія

Кожне налаштування це один із параметрів командного рядка програми. latency: 300 додає 300 мс кожному пакету, jitter: 100 робить цю затримку змінною, loss: 5 губить 5 % пакетів, down і up обмежують швидкість у КБ/с, а loss: 100 відрізає сервер. preset: 'presets.3g' це цілий профіль каналу, а seed: 42 дає ті самі випадкові рішення під час кожного запуску. Сценарій змінює умови з плином секунд: scenario: 'scenarios/cafe-wifi.json'. Крок сценарію може змінити поведінку мережі, але не те, на що націлена сесія.

Паралельні воркери й обмеження

  • По одній. Дві сесії на одному трафіку додалися б, тому паралельні воркери чекають своєї черги, кожен до wait секунд (600, якщо не задати інше значення). Друга сесія в тому самому тесті одразу відхиляється.
  • Вона закінчується разом із тестом. Якщо тестовий воркер помирає, програма це бачить і одразу зупиняється. duration (300 секунд, якщо не задати інше значення) у будь-якому разі найдовший час роботи сесії.
  • Вона каже, коли нічого не зробила. Сесія, яка нічого не сповільнила, бо до її цілі нічого не дійшло, завершується попередженням BadNetworkWarning. Зазвичай це означає, що застосунок говорить з іншою адресою, ніж ціль, наприклад з контейнером.
  • macOS. Програма працює у Windows і Linux. На Mac запускайте тести в контейнері чи віртуальній машині з Linux x86_64 або на ранері CI.
