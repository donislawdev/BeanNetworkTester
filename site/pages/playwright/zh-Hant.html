在 Playwright 測試中模擬慢網路和封包遺失

Playwright 可以讓頁面離線，也可以透過 DevTools 讓 Chromium 變慢。npm 上的 beannetworktester 套件則是在瀏覽器之下拖慢真實的網路：為測試所連線的伺服器加入延遲、封包遺失、限速或完全斷線。Chromium、Firefox 和 WebKit 以同樣的方式變慢，WebSocket 也一樣。套件內含 Bean Network Tester 的程式，並在測試期間於 Windows 和 Linux 上執行它。從 1.1.0 起，每個穩定版本都會發布它。

安裝

npm install -D @playwright/test beannetworktester
npx playwright install chromium

需要 Windows x64 或 Linux x64（glibc 2.39 或更新，例如 Ubuntu 24.04），以及 Node 20 或更新版本。npm 會把適合你系統的程式當作選用相依套件安裝，所以不要排除選用相依套件。

在 Windows 上變更網路需要系統管理員權限：用「以系統管理員身分執行」開啟終端機。在 Linux 上需要 root，或可以免密碼執行 sudo 的使用者，這時只有程式在 sudo 下執行。GitHub 代管的 Windows 執行器以提升的權限執行，Ubuntu 執行器允許 sudo，所以工作流程不需要額外步驟。

在慢網路上的測試

把它儲存為 tests/slow.spec.js，然後執行 npx playwright test：

import http from 'node:http';
import { test, expect } from 'beannetworktester/playwright';

let server;
test.beforeAll(async () => {
  server = http.createServer((request, response) => response.end('<h1>Hello</h1>'));
  await new Promise((done) => server.listen(8000, done));
});
test.afterAll(() => server.close());

test('a page takes longer on a slow network', async ({ page, badNetwork }) => {
  await badNetwork({ server: 'http://localhost:8000', latency: 500 });
  const started = Date.now();
  await page.goto('http://localhost:8000');
  await expect(page.locator('h1')).toHaveText('Hello');
  expect(Date.now() - started).toBeGreaterThanOrEqual(500);
});

測試能通過，是因為頁面確實來得更晚：進出該伺服器的每個封包都要等 500 ms。測試結束後，網路恢復正常。在 Windows 上用 latency: 200 實測：對目標伺服器的請求從 0.8 ms 變為 404 ms，因為請求和回應都要等待；Chromium 中的頁面從 13 ms 變為 416 ms。同時，目標之外的另一個本機伺服器在 1.6 ms 內回應。

手邊沒有權限？badNetwork({ simulate: true, latency: 500 }) 會用虛構的流量執行程式，不改變網路上的任何東西。它用來檢查套件是否裝好，不會拖慢任何東西。

badNetwork fixture

從 beannetworktester/playwright 而不是 @playwright/test 匯入 test 和 expect。呼叫 badNetwork 時會啟動一個工作階段，網路變慢後即完成。無論測試通過、失敗還是當掉，工作階段都會在測試結束時停止，程式的摘要會以 bad-network 附在測試報告中。要在測試中途改變條件，請先停止第一個工作階段，再啟動下一個：

test('the app recovers when the API comes back', async ({ page, badNetwork }) => {
  const outage = await badNetwork({ server: 'http://localhost:8000', loss: 100 });
  await page.goto('http://localhost:3000');
  await expect(page.getByText('Offline')).toBeVisible();
  await outage.stop();
  await expect(page.getByText('Offline')).toBeHidden();
});

在 Playwright Test 之外，require('beannetworktester') 中的 badNetwork 會啟動同樣的工作階段：const session = await badNetwork({ ... })，而 await session.stop() 會結束它並傳回摘要。

工作階段針對什麼

每個工作階段都針對某個目標，只有這部分流量會改變。沒有目標的工作階段會拖慢這台電腦的所有連線，連測試執行器自己的連線也不例外，所以它不會啟動。

  • server: 'http://localhost:3000' 會拖慢到該位址和連接埠的每個連線，無論來自瀏覽器、你的 API 伺服器還是其他任何程式。'db.local:5432' 和伺服器清單也可以。這是首選，在 Windows 和 Linux 上都很精確。
  • process: 'self' 會拖慢測試 worker 以及它啟動的每個程式，例如它的瀏覽器。測試自己啟動的處理程序，以它的 ChildProcess 傳入。
  • dstPort、dstIp 和 target 是程式自己的目標，用它的語法書寫，適用於已知連接埠或位址上的 API。它們會作用於所有符合的東西：dstPort: 443 是這台電腦的每個 HTTPS 連線，包括你的編輯器的連線；target: 'node' 是名稱裡含有「node」的每個程式。

同時給出的目標會互相收窄：server 加上 process: 'self'，只會拖慢這個 worker 到該伺服器的連線。在 Linux 上，process 和 target 最多要在新連線開啟約 0.2 秒後才生效，所以當第一個請求很重要時，請針對伺服器。

工作階段能做什麼

每個設定都是程式的一個命令列選項。latency: 300 為每個封包加 300 ms，jitter: 100 讓這個延遲波動，loss: 5 丟棄 5 % 的封包，down 和 up 以 KB/s 限制速度，loss: 100 則切斷伺服器。preset: 'presets.3g' 是一整套連結設定，seed: 42 讓每次執行做出相同的隨機選擇。情境會隨著秒數推移改變條件：scenario: 'scenarios/cafe-wifi.json'。情境中的步驟可以改變網路的表現，但不能改變工作階段針對的目標。

平行 worker 與限制

  • 一次一個。同一流量上的兩個工作階段會疊加，所以平行 worker 會輪流進行，每個最多等待 wait 秒（未另行指定時為 600）。同一測試中的第二個工作階段會被立即拒絕。
  • 隨測試一起結束。如果測試 worker 當掉，程式會察覺並立即停止。duration（未另行指定時為 300 秒）在任何情況下都是工作階段的最長執行時間。
  • 什麼都沒做時會告訴你。沒有任何流量到達目標、因而什麼也沒拖慢的工作階段，會以 BadNetworkWarning 結束。常見原因是應用程式連線的位址不是目標，例如一個容器。
  • macOS。程式在 Windows 和 Linux 上執行。在 Mac 上，請在 Linux x86_64 容器或虛擬機器中，或在 CI 執行器上執行測試。

套件在 GitHub 上的 README 列出了每個選項，並說明了每則訊息。
