Simulasikan jaringan lambat dan packet loss di tes Playwright

Playwright bisa membuat halaman offline dan memperlambat Chromium lewat DevTools. Paket beannetworktester di npm justru memperlambat jaringan yang sebenarnya, di bawah browser: latensi, packet loss, batas kecepatan, atau pemutusan total, untuk server yang diajak bicara oleh tes Anda. Chromium, Firefox, dan WebKit diperlambat dengan cara yang sama, termasuk WebSocket. Paket ini membawa program Bean Network Tester dan menjalankannya selama tes berlangsung, di Windows dan Linux. Paket ini terbit bersama setiap rilis stabil mulai 1.1.0.

Instalasi

npm install -D @playwright/test beannetworktester
npx playwright install chromium

Butuh Windows x64 atau Linux x64 (glibc 2.39 atau lebih baru, seperti Ubuntu 24.04) dan Node 20 atau lebih baru. npm memasang program untuk sistem Anda sebagai dependensi opsional, jadi jangan lewatkan dependensi opsional.

Mengubah jaringan butuh hak administrator di Windows: buka terminal dengan "Jalankan sebagai administrator". Di Linux butuh root, atau pengguna yang boleh menjalankan sudo tanpa kata sandi, dan saat itu hanya programnya yang berjalan dengan sudo. Runner Windows yang di-host GitHub berjalan dengan hak tinggi dan runner Ubuntu-nya mengizinkan sudo, jadi workflow tidak butuh langkah tambahan.

Tes di jaringan yang lambat

Simpan ini sebagai tests/slow.spec.js lalu jalankan npx playwright test:

import http from 'node:http';
import { test, expect } from 'beannetworktester/playwright';

let server;
test.beforeAll(async () => {
  server = http.createServer((request, response) => response.end('<h1>Hello</h1>'));
  await new Promise((done) => server.listen(8000, done));
});
test.afterAll(() => server.close());

test('a page takes longer on a slow network', async ({ page, badNetwork }) => {
  await badNetwork({ server: 'http://localhost:8000', latency: 500 });
  const started = Date.now();
  await page.goto('http://localhost:8000');
  await expect(page.locator('h1')).toHaveText('Hello');
  expect(Date.now() - started).toBeGreaterThanOrEqual(500);
});

Tes lulus karena halaman memang tiba lebih lambat: setiap paket ke server itu dan darinya menunggu 500 ms. Saat tes selesai, jaringan kembali normal. Diukur di Windows dengan latency: 200: permintaan ke server dalam tujuan naik dari 0,8 ms ke 404 ms, karena permintaan dan jawabannya sama-sama menunggu, dan halaman di Chromium dari 13 ms ke 416 ms. Server lokal lain, di luar tujuan, menjawab dalam 1,6 ms selama itu.

Tidak punya hak akses? badNetwork({ simulate: true, latency: 500 }) menjalankan program pada lalu lintas buatan dan tidak mengubah apa pun di jaringan. Ini memeriksa bahwa paket terpasang dengan benar, tanpa memperlambat apa pun.

Fixture badNetwork

Impor test dan expect dari beannetworktester/playwright, bukan dari @playwright/test. badNetwork memulai sesi saat Anda memanggilnya dan selesai menunggu begitu jaringan sudah lambat. Sesi berhenti saat tes selesai, entah lulus, gagal, atau crash, dan ringkasan program dilampirkan ke laporan tes sebagai bad-network. Untuk mengubah kondisi di tengah tes, hentikan sesi pertama sebelum memulai yang berikutnya:

test('the app recovers when the API comes back', async ({ page, badNetwork }) => {
  const outage = await badNetwork({ server: 'http://localhost:8000', loss: 100 });
  await page.goto('http://localhost:3000');
  await expect(page.getByText('Offline')).toBeVisible();
  await outage.stop();
  await expect(page.getByText('Offline')).toBeHidden();
});

Di luar Playwright Test, badNetwork dari require('beannetworktester') memulai sesi yang sama: const session = await badNetwork({ ... }), dan await session.stop() mengakhirinya serta mengembalikan ringkasan.

Apa yang dituju sebuah sesi

Setiap sesi menuju sesuatu, dan hanya lalu lintas itu yang berubah. Sesi tanpa tujuan akan memperlambat setiap koneksi mesin, termasuk milik test runner sendiri, jadi sesi itu tidak dimulai.

  • server: 'http://localhost:3000' memperlambat setiap koneksi ke alamat dan port itu, dari browser, dari server API Anda, atau dari program lain mana pun. 'db.local:5432' dan daftar server juga bisa. Ini pilihan pertama, dan tepat di Windows maupun Linux.
  • process: 'self' memperlambat worker tes dan setiap program yang dijalankannya, seperti browsernya. Proses yang dijalankan sendiri oleh tes Anda diberikan sebagai ChildProcess-nya.
  • dstPort, dstIp, dan target adalah tujuan milik program sendiri, ditulis dalam sintaksnya, untuk API di port atau alamat yang diketahui. Semuanya menjangkau apa pun yang cocok: dstPort: 443 adalah setiap koneksi HTTPS mesin, termasuk milik editor Anda, dan target: 'node' setiap program dengan "node" di namanya.

Tujuan yang diberikan bersama saling mempersempit: server dengan process: 'self' hanya memperlambat koneksi worker ini ke server itu. Di Linux, process dan target menjangkau koneksi baru hingga sekitar 0,2 detik setelah koneksi dibuka, jadi tujukan ke server bila permintaan pertama penting.

Apa yang bisa dilakukan sebuah sesi

Setiap pengaturan adalah salah satu opsi baris perintah program. latency: 300 menambah 300 ms ke setiap paket, jitter: 100 membuat jeda itu bervariasi, loss: 5 membuang 5 % paket, down dan up membatasi kecepatan dalam KB/s, dan loss: 100 memutus server. preset: 'presets.3g' adalah profil koneksi utuh, dan seed: 42 membuat pilihan acak yang sama di setiap jalannya tes. Sebuah skenario mengubah kondisi seiring detik berjalan: scenario: 'scenarios/cafe-wifi.json'. Langkah skenario boleh mengubah perilaku jaringan, tetapi tidak mengubah apa yang dituju sesi.

Worker paralel dan batasan

  • Satu per satu. Dua sesi pada lalu lintas yang sama akan saling menambah, jadi worker paralel bergantian, masing-masing menunggu hingga wait detik (600 kecuali Anda memberi nilai lain). Sesi kedua dalam tes yang sama langsung ditolak.
  • Ia berakhir bersama tes. Jika worker tes mati, program melihatnya dan langsung berhenti. duration (300 detik kecuali Anda memberi nilai lain) adalah waktu terlama sebuah sesi boleh berjalan dalam keadaan apa pun.
  • Ia memberi tahu saat tidak melakukan apa pun. Sesi yang tidak memperlambat apa pun, karena tidak ada yang sampai ke tujuannya, berakhir dengan BadNetworkWarning. Biasanya aplikasi berbicara dengan alamat lain selain tujuan, misalnya sebuah kontainer.
  • macOS. Programnya berjalan di Windows dan Linux. Di Mac, jalankan tes di kontainer atau mesin virtual Linux x86_64, atau di runner CI.
