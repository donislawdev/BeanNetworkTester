Which ports of another computer answer?

A port scanner asks a computer, port by port, whether something there answers. The {{app.tools.portscan.tab}} tool on the {{app.app.tabs.tools}} tab does it over TCP and UDP, from a window, on Windows and on Linux, and says in plain words what the result means. Scan only computers you are allowed to test: security software and network administrators can see a scan.

How to run a scan

  1. Open the {{app.app.tabs.tools}} tab, then {{app.tools.group.network}} and {{app.tools.portscan.tab}}.
  2. Type the computer's address or name, and the ports the way you type them on the Control page: 22, or 80, 443, or 8000-8100. Or fill them in with {{app.tools.portscan.common}} (common services and development servers), {{app.tools.portscan.well_known}} or {{app.tools.portscan.all}}.
  3. Tick {{app.tools.portscan.tcp}}, {{app.tools.portscan.udp}} or both, and press {{app.tools.portscan.scan}}. {{app.tools.portscan.stop}} ends it early, with the ports it asked.

Ports next to each other with the same answer share one row, next to the service the port usually carries, and a line above the table says what the result means.

What each answer means

AnswerMeaning
{{app.tools.portscan.state.open}}On TCP a program accepts connections on the port. On UDP a service replied to the request.
{{app.tools.portscan.state.closed}}The computer said nothing listens there.
{{app.tools.portscan.state.silent}}Nothing came back in time. On TCP a firewall usually dropped the request. On UDP the port can also be open: a service that does not understand the request stays silent.
{{app.tools.portscan.state.unreachable}}The system says the computer is not there: it is off, or this is not its address.
{{app.tools.portscan.state.denied}}This computer refused to send the request.

On Windows a closed UDP port reads {{app.tools.portscan.state.closed}} only when the program runs as administrator. The Windows firewall keeps that message from programs, and with administrator rights the tool reads it from a copy of the network traffic. Without them, closed UDP ports read {{app.tools.portscan.state.silent}}.

What it sends, and how fast

  • On TCP, a connection that is closed at once with nothing sent on it. On UDP, a real request for DNS, NTP, NetBIOS, mDNS and SSDP, and an empty datagram for any other port.
  • A computer on a network this one is attached to is asked 256 ports at a time, with 1 s for each. One behind a router is asked 32 at a time, at most 20 new a second, with 3 s for each, so the router's table of connections does not fill up. A scan that can take more than five minutes asks first.
  • When 64 ports read {{app.tools.portscan.state.unreachable}} and no other port answered, the computer is not there, and the scan stops asking it.
  • When only a few ports gave no answer and the rest did, those few are asked once more, slower.

{{app.tools.portscan.copy}} copies the table in English, and {{app.tools.portscan.export}} writes the rows to a CSV file.

One port, from the console

To check a single TCP port, PowerShell and most Linux systems already have what you need:

Test-NetConnection example.com -Port 443
nc -zv example.com 443

For service versions or the system on the other end, nmap is the tool. This one answers the question before that: which ports answer at all, over TCP and UDP, with nothing else to install.

A port on this computer instead?

If the question is which program on this computer holds a port, or why a server cannot open one, see which program is using a port.
