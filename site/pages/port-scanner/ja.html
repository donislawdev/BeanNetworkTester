別のコンピューターのどのポートが応答するか

ポートスキャナーは、コンピューターにポートを1つずつ尋ねて、そこで何かが応答するかを調べます。{{app.app.tabs.tools}} タブの {{app.tools.portscan.tab}} ツールは、これを TCP と UDP で、ウィンドウから、Windows でも Linux でも行い、結果の意味をふつうの言葉で伝えます。スキャンするのは、テストしてよいコンピューターだけにしてください。セキュリティソフトやネットワーク管理者にはスキャンが見えます。

スキャンのしかた

  1. {{app.app.tabs.tools}} タブを開き、{{app.tools.group.network}} の {{app.tools.portscan.tab}} を開きます。
  2. 相手のアドレスか名前と、ポートを入力します。ポートの書き方はコントロールページと同じです: 22、80, 443、8000-8100。{{app.tools.portscan.common}} (よく使われるサービスと開発用サーバー)、{{app.tools.portscan.well_known}}、{{app.tools.portscan.all}} で埋めることもできます。
  3. {{app.tools.portscan.tcp}}、{{app.tools.portscan.udp}}、またはその両方にチェックを入れ、{{app.tools.portscan.scan}} を押します。{{app.tools.portscan.stop}} を押すと、それまでに尋ねたポートの結果を残して早めに終わります。

隣り合っていて結果が同じポートは1行にまとまり、そのポートでよく使われるサービスが横に出ます。表の上の1行が、結果の意味を説明します。

それぞれの結果の意味

結果意味
{{app.tools.portscan.state.open}}TCP では、プログラムがそのポートで接続を受け付けています。UDP では、サービスが要求に応答しました。
{{app.tools.portscan.state.closed}}相手のコンピューターが、そこでは何も待ち受けていないと答えました。
{{app.tools.portscan.state.silent}}時間内に何も返ってきませんでした。TCP ではたいていファイアウォールが要求を捨てています。UDP ではポートが開いている可能性もあります。要求を理解できないサービスは黙ったままだからです。
{{app.tools.portscan.state.unreachable}}システムが、そのコンピューターはいないと言っています。電源が切れているか、そのアドレスではありません。
{{app.tools.portscan.state.denied}}このコンピューターが要求の送信を拒みました。

Windows では、閉じた UDP ポートが {{app.tools.portscan.state.closed}} になるのは、プログラムを管理者として実行したときだけです。Windows ファイアウォールはそのメッセージをプログラムに渡さず、管理者権限があるとツールはネットワーク通信のコピーからそれを読み取ります。権限がなければ、閉じた UDP ポートは {{app.tools.portscan.state.silent}} になります。

何を送り、どのくらいの速さか

  • TCP では、何も送らずにすぐ閉じる接続。UDP では、DNS、NTP、NetBIOS、mDNS、SSDP には本物の要求を、それ以外のポートには空のデータグラムを送ります。
  • このコンピューターがつながっているネットワーク内の相手には、一度に 256 ポートを、それぞれ 1 秒待って尋ねます。ルーターの向こうの相手には、一度に 32 ポート、1 秒あたり新規 20 まで、それぞれ 3 秒待って尋ねます。ルーターの接続テーブルをあふれさせないためです。5 分を超えそうなスキャンは、始める前に確認します。
  • 64 個のポートが {{app.tools.portscan.state.unreachable}} になり、ほかのポートがどれも応答しなければ、相手はいないと判断してスキャンはそこへの問い合わせをやめます。
  • ほとんどのポートが応答し、数個だけが応答しなかったときは、その数個にもう一度、ゆっくり尋ねます。

{{app.tools.portscan.copy}} は表を英語でコピーし、{{app.tools.portscan.export}} は各行を CSV ファイルに書き出します。

コンソールで1つのポートを

TCP ポートを1つだけ確かめるなら、PowerShell とほとんどの Linux にはすでに必要なものがあります:

Test-NetConnection example.com -Port 443
nc -zv example.com 443

サービスのバージョンや相手の OS を知りたいなら nmap の出番です。このツールが答えるのはその前の問い、つまり TCP と UDP でどのポートがそもそも応答するかで、ほかに何もインストールする必要はありません。
