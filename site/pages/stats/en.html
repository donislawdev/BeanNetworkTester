Statistics, connections and CSV files explained

What every counter on the {{app.app.tabs.statistics}} tab counts, what every column of the {{app.app.tabs.connections}} tab holds, and what is in each CSV file the program saves. The names and the CSV columns are read from the program when this page is built.

The counters on the {{app.app.tabs.statistics}} tab

Download, upload and the queue show what is happening right now; every other counter adds up from the start of the session. Each one also has a column in the statistics CSV, named below.

{{page.counter_reference}}

{{app.stats.overflow}}, {{app.stats.shutdown_dropped}} and {{app.stats.send_failed}} are packets the tool itself lost, not the damage you asked for. They keep the arithmetic of seen, delivered and dropped honest, but they are not part of the effective loss: any of them above zero means part of the loss you measure is the tool's. Right-click a value to copy it, or use {{app.buttons.copy_counters}} to copy every row as it reads on screen, which is handy for a bug report.

The columns of the {{app.app.tabs.connections}} tab

One row per connection, every column sortable by its header, and each header carries the same explanation as a tooltip.

{{page.column_reference}}

Where the CSV files go

{{app.buttons.export_csv}} on the {{app.app.tabs.statistics}} tab adds a row to one file in your own folder: %LOCALAPPDATA%\BeanNetworkTester on Windows, ~/.config/BeanNetworkTester for the Linux package, and the project folder when run from source. Set BEAN_DATA_DIR to keep it somewhere else. Each row holds the time, whether the capture was narrowed, and then the counters, under the names given above.

A table's export, {{app.buttons.export_conns}} or {{app.tools.sockets.export}} in the tools, asks where to save, and offers a name with the date and time in it, so a second export does not replace the first. The log names the full path of every file the program saves.

The connections CSV

The same rows as the table, but the column names spell out what the table shortens, and sizes are always in bytes, never in the unit the screen picked. The last two columns come after the rest on purpose, so a reader that takes columns by position is not thrown off by them.
