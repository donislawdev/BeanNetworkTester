pytest에서 네트워크 지연과 패킷 손실 시뮬레이션

모의 객체는 없습니다. PyPI의 beannetworktester 패키지는 pytest에 bad_network fixture를 제공해, 테스트 동안 실제 네트워크를 느리게 합니다. 앱, 브라우저, 서버가 실제로 서로 통신하는 동안 한 서버나 한 프로세스에 지연, 패킷 손실, 속도 제한, 완전한 끊김을 더합니다. 패키지에는 Bean Network Tester 프로그램이 들어 있으며, Windows와 Linux에서 이를 실행합니다. 1.1.0부터 모든 안정 릴리스와 함께 게시됩니다.

설치

pip install beannetworktester

Windows x64 또는 Linux x64(glibc 2.39 이상, 예: Ubuntu 24.04)와 Python 3.10 이상이 필요합니다.

네트워크를 바꾸려면 Windows에서는 관리자 권한이 필요합니다. 터미널을 "관리자 권한으로 실행"으로 여세요. Linux에서는 root 또는 비밀번호 없이 sudo를 쓸 수 있는 사용자가 필요하며, 이때 sudo로 실행되는 것은 프로그램뿐입니다. GitHub가 호스팅하는 Windows 러너는 높은 권한으로 실행되고 Ubuntu 러너는 sudo를 허용하므로, 워크플로에 추가 단계가 필요 없습니다.

느린 네트워크에서 하는 테스트

이것을 test_slow.py로 저장하고 pytest를 실행하세요.

import subprocess
import sys
import time
import urllib.request

import pytest


@pytest.fixture
def web_server():
    server = subprocess.Popen([sys.executable, "-m", "http.server", "8000"])
    time.sleep(1)
    yield "http://localhost:8000"
    server.terminate()


def test_a_page_takes_longer_on_a_slow_network(bad_network, web_server):
    bad_network(server=web_server, latency=500)
    started = time.monotonic()
    urllib.request.urlopen(web_server).read()
    assert time.monotonic() - started >= 0.5

테스트가 통과하는 이유는 응답이 실제로 늦게 도착하기 때문입니다. 그 서버를 오가는 모든 패킷이 500 ms씩 기다립니다. 테스트가 끝나면 네트워크는 정상으로 돌아옵니다. Windows에서 latency=200으로 측정한 결과, 대상 서버로 보낸 요청은 요청과 응답이 모두 기다리므로 4 ms에서 404 ms가 되었고, Chromium의 페이지는 61 ms에서 412 ms가 되었습니다. 대상이 아닌 다른 로컬 서버는 그동안 11 ms 안에 응답했습니다.

당장 권한이 없나요? bad_network(simulate=True, latency=500)은 지어낸 트래픽으로 프로그램을 실행하며 네트워크에는 아무것도 바꾸지 않습니다. 패키지가 제대로 설치되었는지 확인하는 용도이고, 아무것도 느리게 하지 않습니다.

bad_network fixture

패키지를 설치하면 pytest가 fixture를 알아서 찾습니다. bad_network를 호출하면 세션이 시작되고, 네트워크가 느려지면 돌아옵니다. 세션은 테스트가 통과하든 실패하든 중단되든 테스트가 끝날 때 멈추며, 프로그램의 요약은 테스트의 user_properties에 들어가고, 거기서 JUnit XML 보고서로 들어갑니다. 테스트 도중 조건을 바꾸려면, 다음 세션을 시작하기 전에 첫 세션을 멈추세요.

def test_the_app_recovers_when_the_api_comes_back(bad_network):
    outage = bad_network(server="http://localhost:8000", loss=100)
    assert app_shows_offline_banner()
    outage.stop()
    assert app_hides_offline_banner()

pytest 밖에서는 from beannetworktester import bad_network가 같은 세션을 시작하고, with bad_network(...) as session:은 블록이 끝날 때 세션을 멈춥니다.

Python용 Playwright

Python용 Playwright는 pytest 위에서 실행되므로 fixture도 같습니다. Chromium, Firefox, WebKit은 WebSocket까지 똑같이 느려집니다. 느린 것은 브라우저가 생각하는 네트워크가 아니라 네트워크 그 자체이기 때문입니다.

from playwright.sync_api import expect


def test_the_spinner_shows_on_a_slow_network(bad_network, page):
    bad_network(server="http://localhost:3000", latency=800)
    page.goto("http://localhost:3000")
    expect(page.get_by_role("progressbar")).to_be_visible()

세션이 겨냥하는 대상

모든 세션은 무언가를 겨냥하며, 그 트래픽만 바뀝니다. 대상이 없는 세션은 테스트 러너 자신의 연결까지 포함해 컴퓨터의 모든 연결을 느리게 만들 것이므로, 아예 시작하지 않습니다.

  • server="http://localhost:3000"는 그 주소와 포트로 가는 모든 연결을 느리게 합니다. 앱이든, 브라우저든, 다른 어떤 프로그램이든 마찬가지입니다. "db.local:5432", ("10.0.0.5", 443), 서버 목록도 쓸 수 있습니다. 이것이 첫 번째 선택이며, Windows와 Linux에서 정확합니다.
  • process="self"는 테스트 프로세스와 그것이 시작한 모든 프로그램(예: Playwright의 브라우저)을 느리게 합니다. 테스트가 직접 시작한 프로세스는 그 subprocess.Popen으로 넘깁니다.
  • dst_port, dst_ip, target은 프로그램 자체의 대상으로, 프로그램의 문법으로 쓰며 알려진 포트나 주소의 API를 위한 것입니다. 일치하는 모든 것에 닿습니다. dst_port=443은 편집기의 연결까지 포함한 컴퓨터의 모든 HTTPS 연결이고, target="python"은 이름에 "python"이 들어간 모든 프로그램입니다.

함께 준 대상은 서로를 좁힙니다. server=와 process="self"를 함께 쓰면 이 테스트에서 그 서버로 가는 연결만 느려집니다. Linux에서 process=와 target은 새 연결이 열린 뒤 최대 약 0.2초가 지나서야 적용되므로, 첫 요청이 중요하면 서버를 겨냥하세요.

세션으로 할 수 있는 일

모든 설정은 프로그램의 명령줄 옵션 중 하나이며, - 대신 _로 씁니다. latency=300은 모든 패킷에 300 ms를 더하고, jitter=100은 그 지연을 흔들고, loss=5는 패킷의 5 %를 버리고, down과 up은 속도를 KB/s로 제한하며, loss=100은 서버를 끊습니다. preset="presets.3g"는 회선 프로필 전체이고, seed=42는 실행할 때마다 같은 무작위 선택을 합니다. 시나리오는 초가 흐름에 따라 조건을 바꿉니다: scenario="scenarios/cafe-wifi.json". 시나리오의 단계는 네트워크의 동작을 바꿀 수 있지만, 세션의 대상은 바꿀 수 없습니다.

pytest-xdist와 제한

  • 한 번에 하나. 같은 트래픽에 두 세션이 걸리면 효과가 더해지므로, pytest-xdist worker는 차례를 기다리며 각각 최대 wait초(따로 정하지 않으면 600) 동안 기다립니다. 같은 테스트 안의 두 번째 세션은 바로 거부됩니다.
  • 테스트와 함께 끝납니다. 테스트 프로세스가 죽으면 프로그램이 이를 알아채고 바로 멈춥니다. duration(따로 정하지 않으면 300초)은 어떤 경우에도 세션이 실행될 수 있는 가장 긴 시간입니다.
  • 아무 일도 하지 않았으면 알려 줍니다. 대상에 아무것도 닿지 않아 아무것도 느리게 하지 않은 세션은 BadNetworkWarning으로 끝납니다. 보통은 앱이 대상이 아닌 다른 주소, 예를 들어 컨테이너와 통신하는 경우입니다.
  • macOS. 프로그램은 Windows와 Linux에서 실행됩니다. Mac에서는 Linux x86_64 컨테이너나 가상 머신, 또는 CI 러너에서 테스트를 실행하세요.

GitHub에 있는 패키지 README에 모든 옵션과 각 메시지의 뜻이 나와 있습니다.
