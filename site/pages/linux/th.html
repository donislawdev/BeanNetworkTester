เครือข่ายแย่บน Linux สำหรับแอปเดียวเท่านั้น

บน Linux คำตอบที่ใช้กันทั่วไปคือ tc กับ netem ซึ่งเพิ่มความหน่วงและการสูญหายให้กับอินเทอร์เฟซเครือข่ายทั้งตัวจากบรรทัดคำสั่ง Bean Network Tester สร้างความเสียหายแบบเดียวกันให้โปรแกรมเดียว จากหน้าต่างหรือจากบรรทัดคำสั่ง และหยุดเองเมื่อครบเวลา เวอร์ชัน Linux ยังเป็นรุ่นทดลอง และหน้านี้บอกว่าสิ่งนั้นหมายถึงอะไร

คำสั่ง tc netem และสิ่งที่ใช้ที่นี่

คำสั่ง netem กับคำสั่งที่ใกล้เคียงที่สุดที่นี่ วางคู่กัน ให้รันด้วย sudo และคง --target กับ --duration ไว้ เพราะถ้าไม่มีสองตัวนี้ ผลจะกระทบทั้งเครื่องเหมือน netem

sudo tc qdisc add dev eth0 root netem delay 100ms 20ms loss 5%
sudo ./BeanNetworkTester --target firefox --latency 100 --jitter 20 --loss 5 --duration 60

ไม่ใช่ทุกตัวเลขที่ย้ายมาได้แบบหนึ่งต่อหนึ่ง netem หน่วงเฉพาะสิ่งที่ออกจากอินเทอร์เฟซ แต่เครื่องมือนี้ดักทั้งสองทิศทาง ดังนั้น --latency 100 จะเพิ่มเวลาไปกลับราว 200 ms หากต้องการหน่วงเฉพาะขาออก ให้เพิ่ม --filter out ความเร็วของ netem เป็นบิตต่อวินาที ส่วนขีดจำกัดความเร็วที่นี่เป็น KB/s หน้า netem อธิบายความต่างแต่ละข้อ

ทำไมไม่ใช้ netem อย่างเดียว

  • โปรแกรมเดียว ไม่ใช่ทั้งอินเทอร์เฟซ netem ทำให้ทุกอย่างที่ออกทาง eth0 ช้าลง รวมถึงเซสชัน ssh ของคุณด้วย ที่นี่ --target เลือกโปรเซสตามชื่อ (บน Linux ไม่มี .exe: firefox, chrome) PID ที่อยู่ หรือพอร์ต ส่วนที่เหลือของเครื่องทำงานตามปกติ
  • สองทิศทาง netem ปรับรูปทราฟฟิกขาออก ส่วนทราฟฟิกขาเข้าต้องใช้อุปกรณ์ ifb และกฎอีกชุดหนึ่ง ที่นี่ดาวน์โหลดและอัปโหลดมีขีดจำกัดของตัวเอง
  • เก็บกวาดเอง กฎของ netem จะอยู่จนกว่าคุณจะลบ เซสชันที่นี่จบหลัง --duration และถ้าโปรแกรมถูกบังคับปิด ทราฟฟิกที่มันกักไว้จะไหลต่อหลังประมาณ 3 วินาที
  • เห็นว่าเกิดอะไรขึ้น มีกราฟ ตารางการเชื่อมต่อ และตัวนับสิ่งที่ถูกหน่วง ถูกทิ้ง และถูกปล่อยผ่าน แทน tc -s qdisc
  • รันซ้ำได้ --seed เล่นซ้ำการสูญหายและจิตเตอร์แบบสุ่มชุดเดิม และ สถานการณ์ตามเวลา เปลี่ยนการตั้งค่าในวินาทีที่กำหนด เหมือนสคริปต์ที่มี tc กับ sleep

สิ่งที่ต้องมี

  • แพ็กเกจ จากหน้ารุ่นที่เผยแพร่ เป็นไฟล์ .tar.gz ที่มี Python และ Tk ของตัวเอง สร้างบน Ubuntu 24.04 และตรวจบน Ubuntu 24.04 และ 26.04 สำหรับ x86_64 และต้องใช้ glibc 2.38 ขึ้นไป
  • เคอร์เนล: Linux 5.10 ขึ้นไปที่สร้างพร้อม BTF การดักจับทำงานบน eBPF
  • Root หรือสิทธิ์ CAP_BPF, CAP_PERFMON, CAP_NET_ADMIN และ CAP_NET_RAW หน้าต่างจะขอรหัสผ่านผู้ดูแลระบบในกล่องโต้ตอบของเดสก์ท็อปเอง บรรทัดคำสั่งต้องใช้ sudo และ --simulate ไม่ต้องใช้ทั้งสองอย่าง
tar -xzf BeanNetworkTester-*-linux-x64.tar.gz
cd BeanNetworkTester
./BeanNetworkTester --install-desktop
sudo ./BeanNetworkTester --doctor

--install-desktop เพิ่มโปรแกรมลงในเมนูแอปพลิเคชัน จึงควรรันโดยไม่ใช้ sudo ส่วน --doctor จะแสดงรายการสิ่งที่เครื่องยังขาด

เครื่องมือเครือข่ายก็ใช้บน Linux ได้

แท็บ {{app.app.tabs.tools}} ตอบคำถามก่อนและระหว่างการทดสอบ ได้แก่ {{app.tools.ping.tab}} (ping ต่อเนื่องพร้อมกราฟ), {{app.tools.nat.tab}}, {{app.tools.portscan.tab}}, {{app.tools.sockets.tab}}, {{app.tools.portcheck.tab}}, {{app.tools.tcphealth.tab}} (ค่าที่เคอร์เนลเก็บไว้สำหรับแต่ละการเชื่อมต่อ แบบที่ ss -ti แสดง) และ {{app.tools.adapters.tab}} (แบบที่ ip addr และ ip route แสดง) {{app.tools.tcphealth.tab}} และ {{app.tools.adapters.tab}} ไม่ต้องใช้ sudo ส่วน {{app.tools.ping.tab}} ต้องใช้เฉพาะเมื่อระบบไม่อนุญาตให้กลุ่มของคุณส่ง ping เช่นบน Ubuntu 24.04

ตอนนี้ Linux ต่างตรงไหน

  • --target อ่านรายการซ็อกเก็ตของระบบ ดังนั้นการแลกเปลี่ยนครั้งแรกของการเชื่อมต่อใหม่อาจผ่านไปก่อนที่เป้าหมายจะมีผล
  • เมื่อเครื่องมือตามไม่ทัน เคอร์เนลจะปล่อยแพ็กเก็ตผ่านข้างเครื่องมือโดยไม่ถูกทำให้เสีย และตัวนับจะบอกว่ามีกี่แพ็กเก็ต
  • ชิ้นส่วน IP ผ่านไปโดยไม่ถูกแตะต้องเสมอ
  • บน Linux ผลรวมตรวจสอบและการรับรองของรุ่นที่เผยแพร่ทำหน้าที่แทนลายเซ็นโค้ด โดยบอกว่าบิลด์ใดสร้างไฟล์ขึ้นมา และ หน้าดาวน์โหลด แสดงวิธีตรวจสอบ

สำหรับการตั้งค่าถาวรของทั้งอินเทอร์เฟซ netem มีอยู่ในเคอร์เนลของคุณแล้วและเป็นเครื่องมือที่ถูกต้อง เครื่องมือนี้มีไว้ทดสอบแอปพลิเคชันหนึ่งตัวเป็นช่วงเวลาหนึ่ง
