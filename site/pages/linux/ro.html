O rețea proastă pe Linux, pentru o singură aplicație

Pe Linux, răspunsul obișnuit este tc cu netem: adaugă întârziere și pierderi unei întregi interfețe de rețea, din linia de comandă. Bean Network Tester face aceleași stricăciuni unui singur program, dintr-o fereastră sau din linia de comandă, și se oprește singur. Versiunea pentru Linux este experimentală, iar pagina aceasta spune ce înseamnă asta.

Comenzile tc netem și ce folosești aici

O comandă netem și cea mai apropiată comandă de aici, una lângă alta. Rulează cu sudo și păstrează --target și --duration: fără ele, efectul cuprinde tot computerul, ca la netem.

sudo tc qdisc add dev eth0 root netem delay 100ms 20ms loss 5%
sudo ./BeanNetworkTester --target firefox --latency 100 --jitter 20 --loss 5 --duration 60

Nu toate numerele se transferă unu la unu. netem întârzie doar ce iese din interfață, iar acest instrument prinde ambele sensuri, așa că --latency 100 adaugă cam 200 ms la un drum dus-întors: adaugă --filter out ca să întârzii doar ce iese. O viteză netem este în biți pe secundă, iar limita de viteză de aici în KB/s. Pagina despre netem explică fiecare diferență.

De ce nu doar netem?

  • Un program, nu toată interfața. netem încetinește tot ce iese prin eth0, inclusiv sesiunea ta ssh. Aici --target alege un proces după nume (pe Linux fără .exe: firefox, chrome), un PID, o adresă sau un port, iar restul mașinii funcționează normal.
  • Ambele sensuri. netem modelează ce iese, iar traficul care intră cere un dispozitiv ifb și un al doilea set de reguli. Aici descărcarea și încărcarea au fiecare limita lor.
  • Face curat după el. O regulă netem rămâne până o ștergi. O sesiune de aici se termină după --duration, iar dacă programul este oprit forțat, traficul pe care îl ținea curge din nou după aproximativ 3 secunde.
  • Vezi ce s-a întâmplat. Un grafic, un tabel de conexiuni și contoare pentru ce a fost întârziat, aruncat și lăsat să treacă, în loc de tc -s qdisc.
  • Rulările se repetă. --seed redă aceleași pierderi și același jitter aleatoriu, iar scenariile în timp schimbă setările la secunde stabilite, ca un script cu tc și sleep.

De ce are nevoie

  • Pachetul de pe pagina de versiuni, un .tar.gz cu propriul Python și propriul Tk. Este construit pe Ubuntu 24.04 și verificat pe Ubuntu 24.04 și 26.04, pentru x86_64, și cere glibc 2.38 sau mai nou.
  • Nucleul: Linux 5.10 sau mai nou, compilat cu BTF. Captura rulează pe eBPF.
  • Root sau capabilitățile CAP_BPF, CAP_PERFMON, CAP_NET_ADMIN și CAP_NET_RAW. Fereastra cere parola unui administrator în dialogul propriu al desktopului, linia de comandă cere sudo, iar --simulate nu cere niciunul dintre ele.
tar -xzf BeanNetworkTester-*-linux-x64.tar.gz
cd BeanNetworkTester
./BeanNetworkTester --install-desktop
sudo ./BeanNetworkTester --doctor

--install-desktop adaugă programul în meniul de aplicații, așa că rulează-l fără sudo. --doctor enumeră ce îi mai lipsește mașinii.

Instrumentele de rețea merg și pe Linux

Fila {{app.app.tabs.tools}} răspunde la întrebări înainte și în timpul unui test: {{app.tools.ping.tab}} (un ping continuu cu grafic), {{app.tools.nat.tab}}, {{app.tools.portscan.tab}}, {{app.tools.sockets.tab}}, {{app.tools.portcheck.tab}}, {{app.tools.tcphealth.tab}} (ce păstrează nucleul pentru fiecare conexiune, cum arată ss -ti) și {{app.tools.adapters.tab}} (cum le arată ip addr și ip route). {{app.tools.tcphealth.tab}} și {{app.tools.adapters.tab}} nu cer sudo, iar {{app.tools.ping.tab}} îl cere doar acolo unde sistemul nu lasă grupul tău să trimită ping, ca pe Ubuntu 24.04.

Unde diferă Linux, azi

  • --target citește lista de socketuri a sistemului, așa că primul schimb al unei conexiuni noi poate trece înainte ca ținta să se aplice.
  • Când instrumentul nu ține pasul, nucleul lasă pachetele să treacă pe lângă el fără să fie stricate, iar contoarele spun câte.
  • Fragmentele IP trec mereu neatinse.
  • Pe Linux, sumele de control și atestarea versiunii țin locul unei semnături de cod: ele spun ce build a produs fișierul, iar pagina de descărcare arată cum le verifici.

Pentru o configurare permanentă a unei interfețe întregi, netem este deja în nucleul tău și este instrumentul potrivit. Acesta este pentru a testa o aplicație o vreme.
