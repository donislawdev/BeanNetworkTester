Linux で1つのアプリだけに悪いネットワークを再現する

Linux でよく使われるのは tc と netem です。コマンドラインから、ネットワークインターフェース全体に遅延とロスを加えます。Bean Network Tester は同じ種類の劣化を1つのプログラムだけに、ウィンドウからでもコマンドラインからでも与え、時間が来れば自分で止まります。Linux 版は試験的なもので、このページではそれが何を意味するかを説明します。

tc netem のコマンドと、ここで使うもの

netem のコマンドと、ここでいちばん近いコマンドを並べます。sudo で実行し、--target と --duration は外さないでください。外すと netem と同じようにコンピューター全体に効きます。

sudo tc qdisc add dev eth0 root netem delay 100ms 20ms loss 5%
sudo ./BeanNetworkTester --target firefox --latency 100 --jitter 20 --loss 5 --duration 60

数値がすべて1対1で移るわけではありません。netem が遅らせるのはインターフェースから出ていくものだけですが、このツールは両方向を捕捉するので、--latency 100 は往復時間に約 200 ms を加えます。出ていくものだけを遅らせるには --filter out を付けてください。netem の速度はビット毎秒で、ここでの速度制限は KB/s です。それぞれの違いは netem のページで説明しています。

netem だけで足りない理由

  • インターフェース全体ではなく、1つのプログラム。netem は eth0 から出ていくものすべてを遅くし、ssh のセッションも例外ではありません。ここでは --target がプロセス名 (Linux では .exe なし: firefox、chrome)、PID、アドレス、ポートで対象を選び、マシンのほかの部分は普段どおり動きます。
  • 両方向。netem が整形するのは出ていくものだけで、入ってくる通信には ifb デバイスと2組目のルールが必要です。ここではダウンロードとアップロードにそれぞれ別の制限があります。
  • 後片付けをする。netem のルールは削除するまで残ります。ここのセッションは --duration のあとで終わり、プログラムが強制終了されても、保持していた通信は約 3 秒後に再び流れます。
  • 何が起きたか見える。tc -s qdisc の代わりに、グラフ、接続テーブル、遅延・破棄・通過したものの件数が見えます。
  • 実行を繰り返せる。--seed は同じランダムなロスとジッターを再生し、時間に沿ったシナリオは決めた秒数で設定を変えます。tc と sleep で書いたスクリプトと同じことです。

必要なもの

  • リリースページのパッケージ: 専用の Python と Tk を含む .tar.gz です。Ubuntu 24.04 でビルドされ、x86_64 向けに Ubuntu 24.04 と 26.04 で確認されています。glibc 2.38 以降が必要です。
  • カーネル: BTF 付きでビルドされた Linux 5.10 以降。捕捉は eBPF で動きます。
  • root、または CAP_BPF、CAP_PERFMON、CAP_NET_ADMIN、CAP_NET_RAW のケーパビリティ。ウィンドウはデスクトップ自身のダイアログで管理者のパスワードを求め、コマンドラインには sudo が必要で、--simulate はどちらも要りません。
tar -xzf BeanNetworkTester-*-linux-x64.tar.gz
cd BeanNetworkTester
./BeanNetworkTester --install-desktop
sudo ./BeanNetworkTester --doctor

--install-desktop はプログラムをアプリケーションメニューに追加するので、sudo なしで実行してください。--doctor は、このマシンにまだ足りないものを一覧にします。

現在の Linux での違い

  • --target はシステムのソケット一覧を読むので、新しい接続の最初のやり取りは、対象指定が効く前に通ることがあります。
  • ツールが追いつけないとき、カーネルはパケットを劣化させずにツールの横を通し、その数はカウンターに出ます。
  • IP フラグメントはいつもそのまま通ります。
  • Linux では、リリースのチェックサムと証明がコード署名の代わりになり、どのビルドがファイルを作ったかを示します。確かめ方はダウンロードページにあります。

インターフェース全体に恒久的な設定をするなら、netem はすでにカーネルに入っていて、それが正しい道具です。このツールは、1つのアプリケーションをしばらくテストするためのものです。
