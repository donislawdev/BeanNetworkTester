在 Linux 上只對一個應用程式模擬弱網

在 Linux 上，常見的做法是用 tc 加 netem：在命令列中為整個網路介面加上延遲與封包遺失。Bean Network Tester 對單一程式造成同樣的損傷，可以用視窗也可以用命令列，並且時間到了會自動停止。它的 Linux 版本仍屬實驗性質，本頁說明這代表什麼。

tc netem 指令與這裡的對應用法

左邊是 netem 指令，右邊是這裡最接近的指令。請用 sudo 執行，並保留 --target 與 --duration：少了它們，就會像 netem 一樣影響整台電腦。

sudo tc qdisc add dev eth0 root netem delay 100ms 20ms loss 5%
sudo ./BeanNetworkTester --target firefox --latency 100 --jitter 20 --loss 5 --duration 60

並非所有數值都能一一對應。netem 只延遲離開介面的流量，而本工具擷取兩個方向，所以 --latency 100 會讓來回時間增加約 200 ms：加上 --filter out 就只延遲送出的流量。netem 的速率以位元每秒計，這裡的限速以 KB/s 計。每一處差異都在 netem 頁面中說明。

為什麼不直接用 netem？

  • 一個程式，而不是整個介面。netem 會拖慢從 eth0 出去的一切，包括你的 ssh 工作階段。這裡的 --target 依處理程序名稱（在 Linux 上不帶 .exe：firefox、chrome）、PID、位址或連接埠選擇目標，電腦的其他部分照常運作。
  • 兩個方向。netem 只整形送出的流量，進入的流量需要 ifb 裝置和第二套規則。這裡下載與上傳各有自己的限速。
  • 自己收拾乾淨。netem 規則會一直存在，直到你刪除它。這裡的工作階段在 --duration 之後結束；如果程式被強制結束，它扣住的流量會在約 3 秒後恢復流動。
  • 看得到發生了什麼。圖表、連線表，以及被延遲、被丟棄和被放行的計數，而不是 tc -s qdisc。
  • 執行可以重複。--seed 會重播相同的隨機封包遺失與抖動，定時情境會在指定的秒數改變設定，就像一個由 tc 和 sleep 組成的指令碼。

需要什麼

  • 發行頁面上的套件：一個內含 Python 與 Tk 的 .tar.gz。它在 Ubuntu 24.04 上建置，在 Ubuntu 24.04 與 26.04 上檢驗，適用於 x86_64，需要 glibc 2.38 或更新版本。
  • 核心：Linux 5.10 或更新版本，並啟用 BTF。擷取以 eBPF 執行。
  • root，或是 CAP_BPF、CAP_PERFMON、CAP_NET_ADMIN 與 CAP_NET_RAW 這些權能。視窗會在桌面自己的對話方塊中要求輸入管理員密碼，命令列需要 sudo，而 --simulate 兩者都不需要。
tar -xzf BeanNetworkTester-*-linux-x64.tar.gz
cd BeanNetworkTester
./BeanNetworkTester --install-desktop
sudo ./BeanNetworkTester --doctor

--install-desktop 會把程式加入應用程式選單，所以執行它時不要加 sudo。--doctor 會列出這台機器還缺少什麼。

目前 Linux 的不同之處

  • --target 讀取系統的通訊端清單，所以一條新連線的第一次交換可能會在目標生效之前通過。
  • 當工具跟不上時，核心會讓封包繞過它而不受損傷，計數會顯示有多少。
  • IP 分段一律原樣通過。
  • 在 Linux 上，發行版本的總和檢查碼與證明取代了程式碼簽章：它們說明檔案是由哪次建置產生的，下載頁面說明如何檢查它們。

如果要為整個介面做長期設定，netem 已經在你的核心裡，它才是合適的工具。本工具用於在一段時間內測試一個應用程式。
