在 Linux 上只对一个应用模拟弱网

在 Linux 上，常见的做法是用 tc 加 netem：在命令行里给整个网络接口加上延迟和丢包。Bean Network Tester 对单个程序造成同样的损伤，既可以用窗口也可以用命令行，并且到时间会自动停止。它的 Linux 版本仍是实验性的，本页说明这意味着什么。

tc netem 命令和这里的对应用法

左边是 netem 命令，右边是这里最接近的命令。请用 sudo 运行，并保留 --target 和 --duration：没有它们，就会像 netem 一样影响整台电脑。

sudo tc qdisc add dev eth0 root netem delay 100ms 20ms loss 5%
sudo ./BeanNetworkTester --target firefox --latency 100 --jitter 20 --loss 5 --duration 60
netem窗口中的设置参数
delay 100ms{{app.fields.latency}}--latency 100
delay 100ms 20ms{{app.fields.latency}}, {{app.fields.jitter}}--latency 100 --jitter 20
loss 5%{{app.fields.loss}}--loss 5
loss 100%{{app.fields.loss}}--loss 100
loss 5% 25%{{app.fields.loss}}, {{app.fields.loss_burst}}--loss 5 --loss-burst 4
duplicate 1%{{app.fields.duplication}}--dup 1
corrupt 0.1%{{app.fields.corruption}}--corrupt 0.1
reorder 25%{{app.fields.spike_prob}}, {{app.fields.spike_ms}}--spike-prob 5 --spike-ms 200
rate 1mbit{{app.fields.download}}, {{app.fields.upload}}--down 122 --up 122
limit 1000{{app.fields.buffer}}--buffer 1000

并非所有数值都能一一对应。netem 只延迟离开接口的流量，而本工具捕获两个方向，所以 --latency 100 会让往返时间增加约 200 ms：加上 --filter out 就只延迟出站流量。netem 的速率以比特每秒计，这里的限速以 KB/s 计。每一处差异都在 netem 页面中说明。

为什么不直接用 netem？

  • 一个程序，而不是整个接口。netem 会拖慢从 eth0 出去的一切，包括你的 ssh 会话。这里的 --target 按进程名（在 Linux 上不带 .exe：firefox、chrome）、PID、地址或端口选择目标，电脑的其余部分照常工作。
  • 两个方向。netem 只整形出站流量，入站流量需要 ifb 设备和第二套规则。这里下载和上传各有自己的限速。
  • 自己收拾干净。netem 规则会一直存在，直到你删除它。这里的会话在 --duration 之后结束；如果程序被强行结束，它扣住的流量会在约 3 秒后恢复流动。
  • 看得到发生了什么。图表、连接表，以及被延迟、被丢弃和被放行的计数，而不是 tc -s qdisc。
  • 运行可以重复。--seed 会重放相同的随机丢包和抖动，定时场景会在指定的秒数改变设置，就像一个由 tc 和 sleep 组成的脚本。

需要什么

  • 发布页上的软件包：一个自带 Python 和 Tk 的 .tar.gz。它在 Ubuntu 24.04 上构建，在 Ubuntu 24.04 和 26.04 上检验，适用于 x86_64，需要 glibc 2.38 或更新版本。
  • 内核：Linux 5.10 或更新版本，并启用 BTF。捕获基于 eBPF。
  • root，或者 CAP_BPF、CAP_PERFMON、CAP_NET_ADMIN 和 CAP_NET_RAW 这些权能。窗口会在桌面自带的对话框中要求输入管理员密码，命令行需要 sudo，而 --simulate 两者都不需要。
tar -xzf BeanNetworkTester-*-linux-x64.tar.gz
cd BeanNetworkTester
./BeanNetworkTester --install-desktop
sudo ./BeanNetworkTester --doctor

--install-desktop 会把程序加入应用程序菜单，所以运行它时不要加 sudo。--doctor 会列出这台机器还缺什么。

{{app.app.tabs.tools}} 选项卡回答测试前和测试中的问题：{{app.tools.ping.tab}}（带图表的持续 ping）、{{app.tools.nat.tab}}、{{app.tools.portscan.tab}}、{{app.tools.sockets.tab}}、{{app.tools.portcheck.tab}}、{{app.tools.tcphealth.tab}}（内核为每个连接保存的数据，和 ss -ti 显示的一样）以及 {{app.tools.adapters.tab}}（和 ip addr、ip route 显示的一样）。{{app.tools.tcphealth.tab}} 和 {{app.tools.adapters.tab}} 不需要 sudo；{{app.tools.ping.tab}} 只有在系统不允许你的用户组发送 ping 时才需要它，例如 Ubuntu 24.04。

目前 Linux 的不同之处

  • --target 读取系统的套接字列表，所以一个新连接的第一次交换可能会在目标生效之前通过。
  • 当工具跟不上时，内核会让数据包绕过它而不受损伤，计数会显示有多少。
  • IP 分片总是原样通过。
  • 在 Linux 上，发布的校验和与证明代替了代码签名：它们说明文件是由哪次构建生成的，下载页面说明如何检查它们。

如果要给整个接口做长期配置，netem 已经在你的内核里，它才是合适的工具。本工具用于在一段时间内测试一个应用。
