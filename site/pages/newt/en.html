An alternative to NEWT, the Network Emulator for Windows Toolkit

NEWT was Microsoft's network emulator for Windows. It added delay, loss and a speed limit to real traffic, so a program could be tried on a bad network from an ordinary PC. Microsoft no longer offers it for download. This page maps each NEWT setting onto Bean Network Tester, which does the same job on Windows 10 and 11.

What happened to NEWT

  • NEWT shipped with the Games for Windows LIVE SDK and the Xbox development kit. Its driver then went into Visual Studio 2010, as the network emulation in load tests.
  • Microsoft has deprecated web performance and load testing in Visual Studio, network emulation included. Visual Studio 2019 is the last version where it is fully available.
  • There is no download from Microsoft today. A search turns up copies on download sites and a Chocolatey package last updated in 2013.

An emulator installs a network driver and runs with administrator rights, so it is worth knowing where an installer comes from before you run it.

NEWT settings, one by one

  • Speed. The speed limit fields are in KB/s, with K = 1024: 122 is about 1 Mbit/s and 1221 about 10 Mbit/s. The netem page has a longer table.
  • Queue. {{app.fields.buffer}} is a time in milliseconds, not a number of packets.
  • Reordering. There is no reorder percentage. A spike holds back a single packet so the ones sent after it overtake it, and the reordered counter on the {{app.app.tabs.statistics}} page shows whether that really happened.
  • Both directions. Each value applies on the way out and on the way back, so --latency 100 adds about 200 ms to a ping. For different values per direction, tick {{app.fields.asym}}, or add --asym and the flags that end in -up.

A typical NEWT link as one command, aimed at one program for two minutes:

BeanNetworkTester.exe --latency 100 --jitter 20 --loss 2 --down 1221 --up 1221 --target myapp.exe --duration 120

What this one brings

  • One program, not the whole computer. Besides an address and a protocol, a filter can be a program, by name or process ID. Aim the impairment at a single app while the rest of the machine stays normal.
  • A command line with exit codes. The same executable runs in CI and reports every outcome through its exit code.
  • Runs you can repeat. With --seed, the same random loss and jitter come back on the next run.
  • Settings that change on their own. Timed scenarios switch the settings at set seconds while you watch the program.
  • A live view. A chart, counters and a table of connections show what was hit and how much.
  • Network tools in the same window. A continuous ping with a chart, a port scanner and a NAT type test.

When to use something else

  • You need a whole network of routers and switches. That is a network simulator, such as GNS3 or EVE-NG, which runs virtual devices. An emulator changes the traffic of one real computer.
  • You want a commercial product with support. SoftPerfect Connection Emulator is a paid network emulator for Windows.
  • You are on Linux. tc netem is built in, and this tool runs there too, as an experiment. See bad network on Linux.
  • You cannot get administrator rights. Changing other programs' traffic needs them, with any tool.
