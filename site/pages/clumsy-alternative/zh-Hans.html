适用于 Windows 的 Clumsy 替代方案

Clumsy 是大多数人最先找到的工具，而且它很好用：免费、MIT 许可、交互式，并且和本工具使用同一个 WinDivert 驱动。如果它能满足你的需要，就用它。本页讲的是它满足不了的那些情况。

无论选哪个，都该看什么

问题为什么它能决定选哪个工具
它能只针对一个应用吗？否则你会影响正在工作的这台机器，包括远程会话，以及你正用来阅读文档的浏览器。
它有命令行吗？流水线没法去点复选框。没有命令行，网络测试就永远无法成为构建的一部分。
一次运行可重复吗？无法重放的随机丢包，只会产生别人无法复现的 bug 报告。
它会自行停止吗？需要你记得手动关闭的工具，最后一定会被一直开着。
你能看出它实际做了什么吗？计数器和连接列表能把“感觉很慢”变成具体的数字。

这个工具带来什么

  • 按进程、PID、地址或端口定位，并跟随进程树，所以拥有三十个子进程的浏览器仍然只是一个目标。
  • 同一个可执行文件就是命令行，每种结果都有退出码，并支持 NDJSON 输出，因此可用于 CI。
  • 带随机种子的运行：同一个随机种子会重放同样的随机丢包和抖动。
  • 现成的配置方案：3G、LTE、卫星、拥挤的咖啡馆、机上 Wi-Fi、56k 拨号调制解调器，让你从可信的起点出发，而不是瞎猜数值。
  • 定时会话和脚本化场景，让影响在你观察应用的同时自行变化。
  • 实时视图：图表、计数器，以及显示哪个连接受到影响的连接表。
  • 英语、波兰语和简体中文界面，没有任何形式的遥测。

如果你是从别的工具转过来的

每次讨论这件事都会出现四个名字，它们并不能互相替代。

你熟悉的它是什么在这里可以期待什么
tc 配合 netemLinux 上的方案，内置于内核，通过命令行操作。搜索 WAN 仿真时往往出现的就是它。Windows 上没有 tc。这是精神上最接近的东西：同样种类的网络损伤，带退出码的命令行，并且用驱动代替了排队规则。
Clumsy一款免费、MIT 许可、交互式的 Windows 工具，使用同一个 WinDivert 驱动。只需要一个窗口和一个过滤器时，就用它。需要按进程定位、带随机种子的运行，以及流水线可以调用的命令行时，请来这里。
NetLimiter一款商业 Windows 产品，用于长期按应用管理带宽。这是另一类工作。本工具是测试仪器：开启一段时间，然后关闭，而且它能降低的远不止速度。
Fiddler 或 Charles可以检查、改写并限制经过它们的流量的代理。同样是另一类工作。代理塑造的是它所代理的流量，并且能看到数据。本工具塑造的是连接本身，包括 UDP，以及任何根本不经过代理的流量。

说白了：如果你想要一个面向单个 Windows 应用、带命令行的网络模拟器，你要找的就是这种工具。如果你想读取和修改应用数据，你需要的是代理；如果你用的是 Linux，那你已经有 netem 了。

什么时候该用别的工具

坦诚相告，比让人白下载一次更划算。

  • 你用的是 Linux 或 macOS。本工具只支持 Windows，而且将来也是如此，因为它建立在 Windows 驱动之上。在 Linux 上，tc 配合 netem 是标准答案，而且不需要额外软件。
  • 你想要的是长期的带宽管理：对整台机器、按应用，并且是作为产品功能而不是测试。这正是 NetLimiter 这类商业流量整形工具的用途。本工具是测试仪器：打算开启一段时间，然后关闭。
  • 你拿不到管理员权限。捕获数据包需要这些权限，没有办法绕过，声称可以绕过的工具并没有真正捕获你的流量。
  • 你需要检查并改写应用数据，而不是让链路变差。那是代理的工作。
