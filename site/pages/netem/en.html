netem and Network Link Conditioner on Windows

On Linux there is tc netem, and on a Mac there is Network Link Conditioner. Windows has nothing built in that adds delay and loss. This page maps what you already know onto Bean Network Tester, and points out where the numbers do not carry over.

netem options, one by one

Add --target and --duration to every command here, or it affects the whole computer.

netemSetting in the windowFlag
delay 100ms{{app.fields.latency}}--latency 100
delay 100ms 20ms{{app.fields.latency}}, {{app.fields.jitter}}--latency 100 --jitter 20
loss 5%{{app.fields.loss}}--loss 5
loss 5% 25%{{app.fields.loss}}, {{app.fields.loss_burst}}--loss 5 --loss-burst 4
duplicate 1%{{app.fields.duplication}}--dup 1
corrupt 0.1%{{app.fields.corruption}}--corrupt 0.1
reorder 25%{{app.fields.spike_prob}}, {{app.fields.spike_ms}}--spike-prob 5 --spike-ms 200
rate 1mbit{{app.fields.download}}, {{app.fields.upload}}--down 122 --up 122
limit 1000{{app.fields.buffer}}--buffer 1000
  • Burst loss. The correlation value in netem is not a burst length. {{app.fields.loss_burst}} is the average number of packets lost in a row, which is the nearest equivalent.
  • Reordering. There is no reorder percentage. A spike delays a single packet so the ones sent after it overtake it, and the reordered counter on the {{app.app.tabs.statistics}} page shows whether that really happened.
  • Queue size. The netem limit counts packets. {{app.fields.buffer}} is a time in milliseconds.

Three differences to know about

Direction. netem delays what leaves an interface, and the reply comes back untouched. This tool captures both directions, so --latency 100 adds about 200 ms to a ping: 100 on the way out and 100 on the way back. To get what netem does, capture outbound traffic only:

BeanNetworkTester.exe --filter out --latency 100 --jitter 20 --target myapp.exe --duration 120

Units. A netem rate is in bits per second. The speed limit fields are in KB/s, with K = 1024. Converting megabits:

netem rateSpeed limit field, in KB/s
1mbit122
5mbit610
10mbit1221
50mbit6104
100mbit12207

Scope. tc shapes a whole network interface and needs root. This aims at one program with --target and needs administrator rights.

The numbers are not Apple's, so treat a profile as a starting point. Every value a profile sets is listed on the reference page.

What you get on Windows

  • One program, not the whole computer. Aim the impairment at a single app while the rest of the machine stays normal.
  • A timeline instead of a shell script. Timed scenarios change the settings at set seconds, which is what a script of tc and sleep does on Linux.
  • A pipeline can run it. The same executable runs in CI and reports through exit codes.

On Linux or macOS, use the originals. This tool runs on Windows only.
