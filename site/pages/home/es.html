Prueba tu aplicación en una mala red

Bean Network Tester añade lag, pérdida de paquetes y límites de velocidad a una sola aplicación de Windows. Verás lo que ven tus usuarios en un tren, en el hotspot de un hotel o con un móvil que solo tiene una barra de cobertura.

Es un emulador de red pensado para un solo programa y no para todo el sistema, así que puedes reproducir un internet lento para la aplicación que estás probando mientras todo lo demás sigue funcionando.

Qué le hace a tu red

La ralentiza

Añade un retardo fijo o aleatorio. Descubre qué hacen 300 ms de ping con tu indicador de carga.

Pierde paquetes

Descártalos, duplícalos o corrómpelos, y observa si tu aplicación se recupera o simplemente se cuelga.

Limita la velocidad

Mantén la descarga o la subida en un número fijo de KB por segundo, como hace un enlace móvil débil.

Corta el enlace

Derriba conexiones, bloquea un puerto o una dirección, o haz que la red vaya y venga.

Apunta a una sola app

Elige un proceso, un PID, una dirección o un puerto. El resto del sistema sigue funcionando con normalidad.

Se repite exactamente

La misma semilla reproduce la misma ejecución. Esa es la diferencia entre un informe de error y una anécdota.

Ponerlo en marcha lleva tres pasos

  1. Descarga el zip desde la página de versiones y descomprímelo donde quieras.
  2. Inicia BeanNetworkTester.exe. Pide por sí mismo permisos de administrador, porque capturar el tráfico los necesita.
  3. Elige un perfil listo para usar, como «{{app.presets.3g}}», pulsa {{app.buttons.start}} y usa tu aplicación.

Hay un modo de texto en el mismo archivo, así que todo también funciona en un pipeline. Un solo comando basta para comprobar que tu servicio sobrevive a un 10 % de pérdida de paquetes:

BeanNetworkTester.exe --loss 10 --target myapp.exe --duration 60

Se detiene solo cuando se acaba el tiempo, así que un paso que se cuelga no puede dejar tras de sí una red rota. Añade --simulate para ensayar un comando sin tocar el tráfico real.

Quién lo usa

Testers que tienen que reproducir el «en mi máquina funciona». Desarrolladores que necesitan que un timeout ocurra de verdad. Desarrolladores de juegos que comprueban qué le hace el lag a su netcode. Cualquiera a quien alguna vez le hayan preguntado si la aplicación funciona con una conexión débil y no haya tenido una forma honesta de averiguarlo.
