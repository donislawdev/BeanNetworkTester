Simulate packet loss from the command line

The same program runs without its window. Give it any option and it works in the console instead, which is how a script or a CI job uses it.

How it starts

On Windows it is the same BeanNetworkTester.exe that opens the window: with no options it opens the window, and with any option it runs in the console and shows no window. From a copy of the source code, write python bean_network_tester.py in its place. On Linux the program is ./BeanNetworkTester in the folder you unpacked, and a real capture needs sudo; Bad network on Linux says what else it needs there.

The command line always speaks English, whatever the language of the window, so its messages read the same in every log.

Try it without risk first

BeanNetworkTester.exe --simulate --loss 20 --duration 10
BeanNetworkTester.exe --doctor
BeanNetworkTester.exe --config my-settings.json --dry-run

The first runs on made-up traffic, so it needs no driver and no administrator rights and cannot touch the network. The second checks this computer: the rights a capture needs, the capture driver, and leftovers from an earlier run. The third reads a settings file and says whether it is valid, without starting anything.

Where the settings come from

Four sources, each one overriding the one before: the defaults, a settings file (--config), a ready profile (--preset) and the flags on the command line. --print-config shows the result as JSON, and --save-config writes it to a file you can load again, in the window or on the command line.

Every setting in the window has a flag of its own, such as --loss or --target. They are listed, with what each one does, on the reference page. The options below are everything else.

What it prints

The log, meant for people, goes to standard error, each line starting with [bean]. Data goes to standard output: a report line every few seconds and a summary at the end. With --format json, standard output carries one JSON object per line: a sample object for each report, and a final summary with the exit code, the seed and the command that repeats the run.

BeanNetworkTester.exe --simulate --duration 30 --format json > run.ndjson

Each way a run can end has its own exit code, so a pipeline can tell a failing application from a tool that could not start. The codes are listed on the reference page.

Examples

Impair one program for a minute, and nothing else on the computer:

BeanNetworkTester.exe --target myapp.exe --latency 200 --loss 2 --duration 60

Impair one server for two minutes, with output a pipeline can read, and fail if nothing was captured at all:

BeanNetworkTester.exe --dst-ip 10.0.0.5 --dst-port 443 --loss 5 --duration 120 --format json --fail-on-no-traffic

Play a ready scenario that does not repeat by itself in a loop for ten minutes, and keep a report that repeats the run:

BeanNetworkTester.exe --scenario scenarios/upload-drop-midway.json --loop --target myapp.exe --duration 600 --repro-out run.json

More recipes for pipelines are on Network tests in CI.
