从命令行模拟丢包

同一个程序也可以不打开窗口运行。只要给它任意一个选项，它就会在控制台中工作，脚本和 CI 任务就是这样使用它的。

如何启动

在 Windows 上，它就是打开窗口的那个 BeanNetworkTester.exe：不带选项时打开窗口，带上任意选项时在控制台中运行，不显示窗口。如果使用源代码副本，请改写为 python bean_network_tester.py。在 Linux 上，程序是解压目录中的 ./BeanNetworkTester，真正的捕获需要 sudo；在 Linux 上模拟弱网 说明了它在那里还需要什么。

无论窗口使用哪种语言，命令行始终使用英语，因此它的消息在任何日志中都一样。

先在没有风险的情况下试一试

BeanNetworkTester.exe --simulate --loss 20 --duration 10
BeanNetworkTester.exe --doctor
BeanNetworkTester.exe --config my-settings.json --dry-run

第一条命令使用模拟的流量运行，因此不需要驱动，也不需要管理员权限，不会影响网络。第二条检查这台电脑：捕获所需的权限、捕获驱动，以及之前运行留下的残留。第三条读取一个设置文件并告诉你它是否有效，不会启动任何东西。

设置从哪里来

有四个来源，后一个覆盖前一个：默认值、设置文件（--config）、现成的配置方案（--preset）以及命令行上的参数。--print-config 以 JSON 显示最终结果，--save-config 把它写入一个文件，之后可以在窗口或命令行中再次加载。

窗口中的每项设置都有自己的参数，例如 --loss 或 --target。它们连同各自的作用列在参考表页面上。下面的选项是其余全部。

它会输出什么

给人看的日志写到标准错误输出，每行以 [bean] 开头。数据写到标准输出：每隔几秒一行报告，结束时一份汇总。使用 --format json 时，标准输出每行一个 JSON 对象：每次报告一个 sample 对象，最后一个 summary，其中包含退出码、种子和可重复这次运行的命令。

BeanNetworkTester.exe --simulate --duration 30 --format json > run.ndjson

每种结束方式都有自己的退出码，因此流水线可以区分是应用程序出错还是工具没能启动。退出码列在参考表页面上。

示例

让一个程序的网络变差一分钟，电脑上的其他一切不受影响：

BeanNetworkTester.exe --target myapp.exe --latency 200 --loss 2 --duration 60

让一台服务器的网络变差两分钟，输出流水线能读取的格式，如果什么都没有捕获到就以失败结束：

BeanNetworkTester.exe --dst-ip 10.0.0.5 --dst-port 443 --loss 5 --duration 120 --format json --fail-on-no-traffic

把一个本身不重复的现成场景循环播放十分钟，并保存一份可以重复这次运行的报告：

BeanNetworkTester.exe --scenario scenarios/upload-drop-midway.json --loop --target myapp.exe --duration 600 --repro-out run.json

更多流水线用法见CI 中的网络测试。
