從命令列模擬封包遺失

同一個程式也可以不開視窗執行。只要給它任何一個選項，它就會在主控台中工作，指令碼和 CI 工作就是這樣使用它的。

如何啟動

在 Windows 上，它就是開啟視窗的那個 BeanNetworkTester.exe：不帶選項時開啟視窗，帶上任何選項時在主控台中執行，不顯示視窗。如果使用原始碼副本，請改寫為 python bean_network_tester.py。在 Linux 上，程式是解壓縮資料夾中的 ./BeanNetworkTester，真正的擷取需要 sudo；在 Linux 上模擬弱網 說明了它在那裡還需要什麼。

無論視窗使用哪種語言，命令列一律使用英文，因此它的訊息在任何記錄中都一樣。

先在沒有風險的情況下試試看

BeanNetworkTester.exe --simulate --loss 20 --duration 10
BeanNetworkTester.exe --doctor
BeanNetworkTester.exe --config my-settings.json --dry-run

第一個指令使用模擬的流量執行，因此不需要驅動程式，也不需要系統管理員權限，不會影響網路。第二個檢查這台電腦：擷取所需的權限、擷取驅動程式，以及先前執行留下的殘留。第三個讀取一個設定檔並告訴你它是否有效，不會啟動任何東西。

設定從哪裡來

有四個來源，後一個覆蓋前一個：預設值、設定檔（--config）、現成的設定組合（--preset）以及命令列上的參數。--print-config 以 JSON 顯示最後結果，--save-config 則把它寫入一個檔案，之後可以在視窗或命令列中再次載入。

視窗中的每項設定都有自己的參數，例如 --loss 或 --target。它們連同各自的作用列在參考表頁面上。下面的選項是其餘全部。

它會輸出什麼

給人看的記錄寫到標準錯誤輸出，每一行以 [bean] 開頭。資料寫到標準輸出：每隔幾秒一行報告，結束時一份摘要。使用 --format json 時，標準輸出每行一個 JSON 物件：每次報告一個 sample 物件，最後一個 summary，其中包含結束代碼、種子和可重複這次執行的指令。

BeanNetworkTester.exe --simulate --duration 30 --format json > run.ndjson

每種結束方式都有自己的結束代碼，因此管線可以分辨是應用程式出錯還是工具沒能啟動。結束代碼列在參考表頁面上。

範例

讓一個程式的網路變差一分鐘，電腦上的其他一切不受影響：

BeanNetworkTester.exe --target myapp.exe --latency 200 --loss 2 --duration 60

讓與一台伺服器的連線變差兩分鐘，輸出管線能讀取的格式，如果什麼都沒擷取到就以失敗結束：

BeanNetworkTester.exe --dst-ip 10.0.0.5 --dst-port 443 --loss 5 --duration 120 --format json --fail-on-no-traffic

把一個本身不會重複的現成情境循環播放十分鐘，並保存一份可以重複這次執行的報告：

BeanNetworkTester.exe --scenario scenarios/upload-drop-midway.json --loop --target myapp.exe --duration 600 --repro-out run.json
