过滤语法：名称、PID、IP 范围、CIDR 和端口

一种小小的语言让工具针对程序、地址和端口。它在窗口和命令行中的用法完全一样，本页上的每个示例都由程序自己的解析器检查过。

在哪里使用

在窗口中：目标进程字段、{{app.frames.destination}}和{{app.frames.block}}下的地址与端口字段，以及两个数据长度字段。在命令行中：--target、--dst-ip、--dst-port、--block-ip、--block-port、--payload-udp 和 --payload-tcp。字段留空表示全部。

基本写法

写法含义示例
a,b,c列表：任意一项匹配即可80,443
a-b范围，包含两端10.0.0.1-10.0.0.50
> < >= <=比较，用于数字和地址>1024
!排除这一项!53
* ?通配符：任意一串字符，或一个字符chrome*
re:正则表达式，不区分大小写re:^chrome\.exe$
a.b.c.d/nCIDR 网段，仅用于地址192.168.1.0/24

逗号两侧的空格会被忽略，两个逗号之间的空位也会被忽略。! 后面什么都没有则是错误：80,! 会被拒绝。

各项如何组合

不带 ! 的项相加：只要其中任意一项匹配，或者根本没有这样的项，值就匹配。带 ! 的项随后把匹配的去掉。顺序无关，所以 80,!53 与 !53,80 相同。

写法匹配
443只有 443 端口
!53除 53 以外的一切，因为没有要相加的项
!53,!443除 53 和 443 以外的一切
1000-2000,!15001000 到 2000，不含 1500
80,443,8000-8100,>9000,!808080、443、8000 到 8100 以及 9000 以上的一切，但不含 8080

程序

一项可以是名称或 PID，一个字段中可以混用。普通名称会在程序名的任意位置匹配，不区分大小写，所以 chrome 会匹配 chrome.exe 和 chromedriver.exe。单独的数字、范围或比较表示 PID。通配符和 re: 匹配名称。对名称做比较（例如 >chrome）会被拒绝，而不是什么都不匹配。

写法匹配
chrome.exe名称中含有 chrome.exe 的所有程序
chrome,!chromedriverChrome，但不含 chromedriver
chrome.exe,firefox.exe同时两个程序
12345一个 PID
1000-2000该范围内的所有 PID
firefox*以 firefox 开头的名称
re:^(chrome|firefox)\.exe$恰好是 chrome.exe 或 firefox.exe
firefox,12345一个字段中同时写名称和 PID

数据包只携带地址和端口，从不携带程序名称，所以工具会找出每个匹配程序占用的本地端口并针对这些端口，同时跟踪它新打开的连接。少数端口会被多个程序同时共用（mDNS 5353、SSDP 1900、DHCP 67 和 68）。在这些端口上只能全有或全无，日志会说明是哪一种。

地址

IPv4 和 IPv6 都支持，一个字段中可以混用：针对一种地址族的规则永远不会匹配另一种地址族的地址。地址的写法无关紧要，所以 2001:0db8:0000:0000:0000:0000:0000:0001 和 2001:db8::1 是同一个地址。

写法匹配
1.2.3.4,8.8.8.8两个地址
10.0.0.1-10.0.0.50,!10.0.0.7中间挖掉一个的范围
192.168.1.0/24整个子网
192.168.1.*同一个子网，用通配符表示
!8.8.8.8除 8.8.8.8 以外的所有地址
2001:db8::/32一个 IPv6 子网
10.0.0.0/8,2001:db8::/32一个字段中同时有 IPv4 和 IPv6

端口

端口范围是 0 到 65535；99999 会被拒绝，而不是被跳过。数据长度字段使用相同的语法，按数据字节数计算。

写法匹配
8000-8100范围，包含两端
>1024高位端口
<=1024特权端口
80,443,8000-8100,!8080混合写法

正则表达式

只有前面加上 re: 的项才是正则表达式，所以 chrome.exe 中的点仍然是点。模式不区分大小写，可以在文本的任意位置匹配；要匹配整个文本，请使用 ^ 和 $。模式中的逗号需要加反斜杠，因为逗号用来分隔各项：re:^ch.{1\,8}e\.exe$ 可以正常使用。如果不加反斜杠，re:^ch.{1,8}e\.exe$ 会在逗号处被切成两项，两项都能加载，但匹配的是别的东西。

重复里面再套重复，例如 re:^(\w+)+$，会因为太慢而被拒绝：遇到一个几乎匹配的名称就可能耗费数秒，而地址在每个数据包上都要检查。请只写一次重复：re:^\w+$。

容易踩的坑

  • chrome 会匹配 chromedriver，而 chrome.exe 不会：普通名称只是名称的一部分。
  • chrome* 也会匹配 chromedriver。要恰好匹配一个程序，请写 re:^chrome\.exe$。
  • 端口字段中的 8* 是针对数字文本的通配符，所以它匹配 8、80、8080 和 8443，但不匹配 443。你几乎总是想要一个范围，例如 8000-8999。
  • !53 也包括完全没有端口的流量，例如 ping，因为 ping 数据包不是 53 端口。
  • 同时设置了地址和端口时，两者都必须匹配。如果只想满足其中之一，请分两次运行。
  • 倒着写的范围 2000-1000 会被拒绝。
  • 通配符不是正则表达式：在 re:chrome* 中，星号重复的是字母 e。

每个错误都会立即报告：窗口中的字段变红，并在下方显示原因；命令行则以一条易读的消息结束。
