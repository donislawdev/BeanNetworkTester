**Bean Network Tester** 是一款面向测试人员和开发者的工具：检验你的应用在糟糕的网络连接下表现如何。
和 Clumsy、NetLimiter 一样，它能让你故意把网络变差：增加 ping、丢弃数据包、限制速度、
切断连接等等。它通过 **[WinDivert](https://www.reqrypt.org/windivert.html)** 驱动
（经由 **[PyDivert](https://github.com/ffalcinelli/pydivert)**）拦截流量，既提供带有工具提示、
清晰易用的窗口界面，也提供可用于 CI 的命令行模式。

⭐ **如果它帮你节省了时间，请点个 Star。** 这样下一位需要它的测试人员才会知道它的存在。

**它能做什么**

- **增加延迟和抖动**：固定或随机的延迟，外加偶发的延迟尖峰。
- **丢弃、损坏或重复数据包**：丢包可以成串出现，就像真实的无线链路出故障时那样。
- **限制下载/上传速度**：限速到指定的 KB/s，并带有一个缓冲区，在开始丢包之前先增加排队延迟。
- **断开连接**：TCP 重置、链路中断，或者永远建立不起来的新连接。
- **让链路时通时断**：忽有忽无的中断。
- **破坏路径，而不只是数据包**：MTU 黑洞和 NAT 式的空闲超时。
- **阻断端口或 IP**：内置一个小型防火墙，另有局域网模式（无互联网）和仅互联网模式（无本地网络）。
- **只针对一个应用**：按进程名、PID、IP、端口或某一种地址族来指定。
- **预设与已保存的配置方案**：56k 调制解调器、咖啡馆 Wi-Fi、卫星网络、机上 Wi-Fi 等等。
- **运行脚本化场景**：按时间点执行的步骤，自动改变网络状况。
- **为限速设置计划**：循环重复的速率时间线，无需编写场景。
- **按随机种子重现**：重放完全相同的随机丢包和抖动。
- **把 bug 完整地交给别人**：报告里包含每一项设置、计数器，以及能重复这次运行的命令行。
- **实时观察**：图表、计数器、可搜索的连接表和事件日志。
- **导出为 CSV**：会话统计数据，以及连接表的快照。
- **命令行模式**：可用脚本调用，适合 CI，带有退出码和 JSON 输出。
- **无遥测，不会自行发送任何内容**：Ping 工具只 ping 你输入的地址。

## 快速开始（3 步）

1. 下载 `BeanNetworkTester`：**zip** 包无需安装即可运行，**`.msi`** 则会为这台电脑上的所有用户安装，
   加入 `PATH` 和开始菜单（需要管理员权限）。也可以自己构建：`pyinstaller --noconfirm BeanNetworkTester.spec`。
2. 运行 `BeanNetworkTester.exe`：程序会**自行请求管理员权限**（WinDivert 需要这些权限）。
   在源码仓库中则运行：`python bean_network_tester.py`。
3. 从“配置方案”列表中选择一个预设（例如“3G 网络”），然后点击 **开始**。

**同一个文件**也能运行文本模式：`BeanNetworkTester.exe --simulate --loss 10 --duration 5`。

窗口顶部有一条“已启用：...”状态栏，概括你当前正在做的事情
（例如 *已启用：延迟 +150 ms，1% 丢包，下载 ≤ 384 KB/s*）。把鼠标悬停在任意字段上，
就会弹出工具提示，说明它的作用。

> 注意：选择预设只会填写各个字段，只有点击 **开始** 后才会施加弱网影响。
> 没有管理员权限，WinDivert 驱动无法加载。

如果你想完成某个具体的任务，而不是通读下面的完整手册，请看
[网站上的指南](https://beannetworktester.donislawdev.com/zh-hans/)：它们依次介绍了丢包、
延迟、限速、只针对单个应用，以及在没有互联网的情况下测试，每篇都给出值得尝试的数值和对应的命令。
另有两篇讲的是如何找出哪个程序占用了某个端口，以及用什么来替代 `tc netem` 或 Network Link Conditioner。
这些指南有 22 种语言版本，从英语、波兰语到阿拉伯语、越南语都有。

## 语言

翻译保存在 **`lang/<code>.json`** 文件中（自带：`lang/en.json`、`lang/pl.json` 和
`lang/zh.json`，后者是简体中文）。启动时，应用会**扫描 `lang/` 目录**，自动检测可用的语言。
如果有与系统区域设置匹配的翻译，启动语言就会跟随系统，否则回退到英语。系统设置为繁体中文时同样使用英语：
自带的文件是简体中文，而两者是不同的文字体系，并不是同一种文字的两种拼写。
设置窗口（右上角的齿轮）中的**语言**列表可以随时切换，界面会以所选语言重建，同时保留你当前的设置。

界面中的**所有内容**都已翻译：选项卡、标签、按钮、工具提示、列标题、统计数据、会话面板、事件日志、
日志消息、对话框，以及错误消息（向用户显示的异常）。代码里只使用**键**（例如 `app.tabs.statistics`），
文本来自语言文件。所选语言缺少某个键时使用英语，实在没有就显示键本身。
（命令行，即 CLI，**始终使用英语**，与系统语言和界面语言无关。）

**添加新语言**不需要改动代码：把 `lang/en.json` 复制为例如 `lang/de.json`，翻译其中的值，
并填写头部的 `"_meta": {"code": "de", "name": "Deutsch"}`，重启后该语言就会出现在列表中。
损坏的语言文件会被跳过（不会导致应用崩溃）。

## 系统要求

- Windows 10/11（64 位），Python 3.10+（带 tcl/tk 选项）
- 管理员权限
- `pydivert`（捕获流量），`psutil`（后备方案，见下文）

从源码安装可在 Python 3.10 及更新版本上运行。CI 只在 **3.14** 上测试和构建，
发布的 `.exe` 正是用这个版本冻结打包的，所以更旧的版本受支持，但不会在每次提交时重新验证。

在 Windows 上，Python 3.10 到 3.12 以 15.6 ms 为步长计时。每个数据包都按这个时钟计时，
所以比一个步长更精细的延迟、抖动和速度限制，只能按整数个步长体现，`--doctor` 会就此给出警告。
Python 3.13 及更新版本以及 `.exe` 则以微秒计时。

`psutil` 会随工具一起安装，但在 Windows 上让进程定位生效的并不是它。
在 Windows 上，套接字表和进程名直接来自操作系统，即使完全卸载 `psutil`，定位也照常工作
（实测：映射了 310 个端口，37 个名称全部解析成功）。它是其他系统上的后备方案，
引擎的测试正是靠它在没有任何驱动的 Linux 上运行的。

## 窗口界面

窗口会**自动适应屏幕和系统缩放（DPI）**。初始大小根据分辨率计算
（在 1366x768 上刚好放得下，在 Full HD / 2K / 4K 上则相应变大），所有尺寸，
包括列宽、表格行高、图表边距和文字换行，都随字体缩放。程序声明自己**支持 Per-Monitor-V2 DPI**，
所以把窗口移到缩放比例不同的第二块显示器上，界面也不会变模糊。

窗口大小和位置、当前选中的选项卡、语言、已折叠的分区、日志与选项卡之间的分割位置，
以及表格排序方式，都会记录在 `bean_network_tester_ui.json` 中（与配置方案放在一起）。
保存的窗口几何信息在使用前会先校验：留在第二块显示器上的窗口会在那里重新打开，
如果那块显示器已不存在，则回到当前屏幕的中央。

- **控制**：所有弱网效果设置，按**可折叠的分区**分组（折叠状态会被记住）。
  窗口较宽时，各分区会**排成两列**（而不是一列窄栏加空荡荡的右半边），因此需要滚动的地方少得多。
  整个选项卡都可以滚动，包括用**鼠标滚轮**。
- **统计**：三个子选项卡，所以小屏幕上不会有内容被裁掉：
  - **实时**：计数器（数据包、已丢弃、已损坏、被断开等）和吞吐量图表。
    计数器网格会根据窗口宽度自动选择列数。另有一个“导出 CSV”按钮。
  - **会话**：随机种子、持续时间、已用数据量、峰值，外加“标记故障时刻”“保存复现报告...”
    “复制 CLI 命令”按钮。
  - **事件**：事件日志（开始/停止/更改/场景/故障/重置）。
- **连接**：查看被测系统正在与哪些 IP:端口通信。每一列都在下面的
  [连接列](#连接列)中有说明，每个列标题上也有相应的工具提示。没有端口的流量，
  即 ping（ICMP），同样会被列出，每个地址占一行，端口单元格留空。
  - **“下载”“上传”“总计”是应用实际收到的数据量**，与会话面板中的“已下载（MB）”是同一个量。
    **“观测下载”“观测上传”是工具在施加任何弱网影响之前捕获的数据量**。
    什么都没设置时两者相等。一旦加入丢包或限速，两者就会分开，
    **两者之间的差距就是这条连接受到的损害**。把鼠标悬停在任一列上可以看到完整的说明。
    （这一拆分之前只有一对数值，它放的是捕获到的字节数，列标题却表示已送达：
    一行可能显示收到 5 MB，而对应的应用实际只得到 0.4 MB。）此外还有搜索框（带防抖，
    不会在每次按键时都刷新表格）、点击列标题排序、“**冻结**”（行不再从光标下溜走）
    以及**右键菜单**：复制此行 / 复制 IP 地址、“**将此进程设为目标**”、
    “**仅限此 IP:端口**”，一次点击就能填好过滤字段。
    “**重置此连接**”会立即中断这一条连接，无论会话是否在运行：使用该连接的程序会收到错误，
    对端会收到 TCP 重置。会话期间，这个重置会像其他数据包一样经过各项弱网处理，
    所以严重的丢包可能让它在半路被丢掉。它只适用于 IPv4 上的 TCP
    （Windows 没有办法重置 IPv6 连接），因此其他行上该菜单项呈灰色，而且需要管理员权限。
    表格是**虚拟化**的：只绘制屏幕上实际可见的行，所以不管是 400 行还是几十万行，滚动都是即时的。
    原先 400 行的硬性上限已经取消，显示多少行由“**行数上限**”字段决定
    （位于*表格*分区，0 = 不限制，默认 50 000）。
- **工具**：一些小帮手，解决你在测试之前或测试期间会遇到的问题，每个一个子选项卡。
  这个选项卡上只有 **Ping** 会通过网络发送数据：从 Start 到 Stop，向你输入的地址发送回显请求。目前有：
  - **套接字**：这台电脑上的每个 TCP 和 UDP 套接字，类似 `netstat -ano`，无需会话：
    哪些在监听、哪些已连接、状态（LISTEN、ESTABLISHED、TIME_WAIT 等）以及所属的程序。
    可以用它在施加弱网影响之前看看你的应用监听哪个端口，或者哪个程序占用了某个端口。
    表格在打开选项卡以及按下**刷新**时读取。搜索方式与连接表相同
    （`lport:8080`、`state:listen`、`proc:chrome`），右键点击某一行，可以将其程序设为目标、
    排除它，或者仅限或阻断其远程地址。不需要管理员权限也能显示程序名。
  - **端口是否空闲**：你的程序能使用某个端口吗？输入一个端口、一个列表或一个范围，
    写法与在“控制”页输入端口相同（`8080`、`80, 443`、`9000-9100`，一次最多 1000 个），
    然后按**检查**（或回车）。每个端口都会针对 TCP 和 UDP、IPv4 和 IPv6 逐一检查，
    并标记为**空闲**、**已占用**（附带占用它的程序及其 PID）或**被 Windows 保留**，
    后者是 Windows 划出的一个范围，通常就是服务器明明看似没人用的端口却无法启动的原因。
    这些范围是按协议分别划定的，所以一个端口可能对 UDP 空闲而对 TCP 不空闲。
    对每个端口，工具都会在本机自己的环回地址上向系统申请它，然后立刻把端口还回去。
    谁占用了端口，来自与**套接字**相同的那张表。右键点击某一行，可以将占用该端口的程序设为目标或排除它。
  - **表达式测试**：从“控制”页选一个字段（目标进程、目标 IP 或端口、阻断的 IP 或端口），
    输入一个表达式和一个值，立刻看到两者是否匹配。它还会显示表达式的哪一部分选中了这个值、
    哪个 `!` 部分把它排除了，以及程序如何理解你输入的内容。不是地址、端口或 PID 的值，
    会被指出这一点，而不是简单地报“不匹配”。
    **在“控制”页的字段中使用**会把该表达式放进那个字段，并替换其中原有的内容。
    你输入的内容会保留到关闭程序为止，即使切换了语言也不会丢。
  - **网卡**：这台电脑上的每个网卡，以及测试所依赖的设置，也就是 `ipconfig /all` 打印的那类信息
    （仅限 Windows）。互联网流量所经由的网卡排在最上面，
    其后是正常工作的网卡。选择一个网卡，可以看到它的地址（含前缀）、
    网关、DNS 服务器、DHCP、MAC 地址、MTU 和链路速度。当另一台设备使用同一个地址时，会有提示说明。
    列表在打开选项卡以及按下**刷新**时读取。右键点击网关或 DNS 服务器，可以把它的地址
    填入“控制”页的目标 IP 字段（那里的端口保持不变）。第一行**代理**显示程序是否经过代理：
    此帐户的设置（自动检测、设置脚本、代理服务器以及哪些流量绕过它）、
    Windows 服务使用的代理（WinHTTP），以及 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`
    和 `NO_PROXY` 变量。使用代理的程序连接的是代理，而不是你的目标，
    所以请右键点击代理服务器，把弱网影响限定在它的地址上。
    以名称给出的代理不会被查询解析，地址中的密码会被隐藏。
    **复制报告**会以英语复制所有网卡和代理设置，文本中包含这台电脑的地址和 MAC 地址。
  - **诊断**：不用控制台就能知道开始为什么无法工作。它运行与 `--doctor` 相同的检查
    （管理员权限、WinDivert 驱动、临时文件夹中的残留等），并把每一项标记为正常、注意或问题。
    **清理驱动**会卸载遗留的、仍处于加载状态的 WinDivert 驱动（仅限管理员，会话期间绝不可用）。
    **复制环境报告**会复制 `--version` 一行和 `--doctor` 的输出，可直接粘贴进 bug 报告。
    报告中包含文件夹路径，而路径里可能带有你的 Windows 用户名。勾选
    **包含网卡**或**包含代理设置**，可以把网卡或代理信息也放进报告，两者在勾选之前都是关闭的，
    因为地址会暴露这台电脑所处的网络。
- 底部：**开始/停止**、**应用更改**和**加载/保存文件**，下方是日志。
  这一栏固定在底边，任何选项卡都不会遮住它。

### 更改何时生效

**没有任何东西会自动生效。** 预设、配置方案、局域网模式和加载的配置文件**只会填写表单**。
它们只能通过“**应用更改**”作用到正在运行的会话，当表单与引擎实际正在做的事情不一致时，
这个按钮会**高亮**。标题下方的状态栏会告诉你当前看到的是什么：

| 前缀 | 含义 |
|---|---|
| `Preview:`（界面显示为“预览：”） | 应用已停止，这里描述点击开始后会发生什么 |
| `Active:`（界面显示为“已启用：”） | 这正是此刻施加在流量上的内容 |
| `Unapplied changes:`（界面显示为“尚未应用：”） | 表单已被修改，请点击“应用更改” |

会话运行期间有**两个元素会被锁定**（停止后解锁）：**流量过滤器**（只在开始时生效）和**语言选择器**
（切换语言会重建整个界面）。停止按钮是红色的，不会与开始按钮混淆。

如果某个字段已被另一项设置接管，它会**连同标签一起变灰**，并附有说明，指出是哪项设置接管了它。
设置了计划时，“下载”/“上传”就是这样，因为吞吐量改由计划中的步骤决定。
你一眼就能看出实际生效的是什么。

## 全部选项详解

**要修改的流量**：到底捕获哪些流量。选项有：双向（TCP+UDP+ICMP）、仅出站、仅入站、仅 TCP、
仅 UDP、仅 ICMP（Ping）、仅环回（127.0.0.1/::1，用于测试本地进程之间的通信）。
每个过滤器都同时涵盖 **IPv4 和 IPv6**。（如果 ping“没有反应”，几乎总是因为所选的过滤器不包含 ICMP。）

**环回流量算作上传。** 不管选择哪个过滤器，Windows 都会把这台电脑上两个程序之间对话的两个方向
都当作出站交给我们。对于这类流量，**下载**、计划中的下载列和 **NAT 超时**都不起作用，
上传另设数值时，主数值也不起作用。**上传**限速对两个方向合计生效，而目标进程只会在它发送的部分受到影响。
使用环回过滤器时，应用这类设置，程序会给出提示。

> **注意：** 不存在端口预设（“仅 DNS/HTTP/HTTPS”）。要按端口缩小范围，请使用“目标地址筛选”中的
> **端口**字段，它支持列表、范围和排除（`80,443,8000-8100`、`!53`）。
> 两个地方都能决定端口，而且语义不同，只会造成混乱。

**流量过滤器**在开始时生效，所以运行期间它是**锁定**的：要更改，请先停止（停止按钮），
选择另一个，再重新开始（开始按钮）。

**局域网模式**：一个名为“局域网模式（仅本地网络，不访问互联网）”的复选框。它会拒绝往返于公网（互联网）
地址的流量，放行本地网络：10.0.0.0/8、172.16-31.x、192.168.x、环回、链路本地地址和 CGNAT。
它模拟“局域网正常，互联网中断”，用来测试应用在没有互联网时的表现
（例如没有网关/WAN，或者遇到强制门户）。

**仅互联网**：与它相反，在同一分区中有一个“仅互联网（禁用本地网络）”复选框。它会丢弃往返于
那些同样的本地地址的流量，而让互联网保持正常，
这样你就可以在 WAN 一切正常的情况下，测试与内网服务器、NAS 或打印机通信的应用。
它有两件事不会做，而且两件都很重要：

- **环回依旧可用。** 127.x 和 `::1` 无论如何都会放行，所以本地开发服务器、你自己机器上的数据库，
  以及任何通过环回与自己通信的东西都不受影响。这是有意为之：你自己的机器与自己通信，不算“本地网络”。
- **路由器属于本地网络。** 如果你的电脑向路由器查询 DNS，名称解析会随之中断，
  于是即使互联网流量正被放行，互联网看起来也像坏了。如果这碍事，测试期间请改用公共解析器。

两个复选框可以同时开启。这是允许的，效果是切断除环回之外的一切。
应用时程序会在日志中说明这一点，两个计数器也各自报告自己的那一半。

**目标进程**：把影响范围缩小到所选的应用：进程名（例如 `chrome.exe`）、PID、逗号分隔的列表、
PID 范围、通配符或正则表达式，详见[过滤语法](#过滤语法进程--ip--端口)。
这台机器的其余流量不受影响。字段为空 = 所有流量。

**限速**：下载（入站）和上传（出站）分别设置的最大吞吐量，单位为 KB/s。0 = 不限制。
Ping 是小数据包，所以限速几乎不会改变它，要测试限速，请下载一个文件。
正数总是会限制点什么：极小的限速值（低于 1 B/s）会被提升到 1 B/s，而不会悄悄变成“不限制”。

**速度单位（设置窗口）**：统计页、图表以及这两个字段旁边的读数，用 `KB/s`、`Mbit/s` 还是 `MB/s`
显示吞吐量。它改变的是你所**读**到的内容，而不是你输入的内容：限速本身仍然以 KB/s 为准，
因为保存的配置文件、吞吐量计划、随程序提供的场景、`--down`/`--up` 以及 NDJSON 输出携带的都是这个数值。
选定一个单位后，字段旁边会出现灰色的 `(= 8.39 Mbit/s)`，
这样你既能输入工具需要的数字，又能读到你的链路对外标称的数字。

> **这里的 `K` 是 1024，而一兆比特是十进制的一百万**，两种约定不会相互抵消，
> 所以 1024 KB/s 是 **8.39 Mbit/s**，而不是 8。这是诚实的换算，不是舍入误差：
> 一个字节是 8 位，`1024 x 1024 x 8 = 8 388 608` 比特每秒，而兆比特在所有出售链路的地方都表示 10^6 比特。
> 想让限速与宣传的速度一致时，请除以 8.39，而不是除以 8。

**缓冲区**：限速时链路缓冲区的容量，单位为毫秒（0 = 缓冲区无限）。
它决定了在受限链路上，在开始丢弃多余数据（缓冲膨胀）之前，可以积累多少排队延迟。
没有这个缓冲区，令牌桶可能会“跑”到未来几十秒之后：数据包带着极端的延迟，
而且在会话中途提高限速（例如“链路恢复”的计划步骤）也不起作用，因为积压的数据吞掉了每一个更快的步骤。
设有 `N` ms 的缓冲区时，延迟被限制在约 `N` ms 以内，多余的部分计入“因限速丢弃”
（一个单独的计数器，既不是“丢包”也不是“缓冲区溢出”），提高限速后，
吞吐量会在约 `N` ms 内恢复。默认 1000 ms。只有设置了下载/上传限速或计划时才生效。
缓冲区中的时间会叠加在*延迟*之上，与真实链路一样：延迟 200 ms 加上已满的 150 ms 缓冲区，
一个数据包约 350 ms 后到达。

**延迟（Ping）**：*延迟*：给每个数据包增加多少毫秒。*抖动*：延迟的随机变化（+/- ms），
它会让 ping 上下跳动并让数据包乱序。有三点值得了解：

（0）**Ping 的增幅约为你所设延迟的两倍。** 延迟加在每个数据包上，在默认的双向流量过滤器下，
请求和应答都会被加上，所以 `--latency 100` 显示出来大约是 +200 ms 的 ping
（实测：`--latency 200` 把环回 ping 从不到 1 ms 提高到约 408 ms）。请选择你想要的 ping 的一半。
抖动**不会**同样翻倍：每个数据包都抽取各自的值，所以波动大约增长到 1.4 倍，只有在极端情况下才达到 2 倍。
内置预设就是按这个方法调出来的：`Satellite (geostationary)` 取 340 ms，得到真实地球同步卫星链路
约 680 ms 的 ping。

（1）抖动给每个数据包增加独立的随机延迟，所以数据包可以在队列中互相超越，
抖动本质上会让**数据包乱序**（真实的网络也是如此）。
（2）负的波动会被截断为零，所以当抖动**大于延迟**时，平均附加延迟会高于延迟本身
（例如延迟 0、抖动 50 ms，约一半的数据包没有延迟，平均值约 12 ms，而不是 0）。
当延迟大于抖动时，这种影响可以忽略不计。

*延迟尖峰*位于同一个分区，因为尖峰也是延迟，只是偶尔出现的大延迟。
以给定的概率，它会给**单个数据包**附加额外的延迟（ms），这正是瞬间“卡顿”实际到来的方式。
这个概率是针对每个数据包的，并且**在每个方向上**都生效，所以一次往返遇到它的频率，
大约是这个数字所显示的两倍。

**测试乱序到达**：这正是尖峰这一对设置的用途，也是这个分区叫作“延迟（Ping）与数据包顺序”的原因。
被施加尖峰的数据包会在比它晚发送的数据包之后才到达，所以*尖峰概率*和*尖峰幅度*会让流量乱序，
而**不会**像抖动那样把其他每个数据包的延迟都抹得一团糟。当被测对象是必须自己应对乱序的 UDP 协议时，
这一点很重要：游戏、QUIC、遥测、语音。请把尖峰幅度设得大于数据包之间的间隔，否则不会有任何数据包超越其他数据包。

是否真的发生了乱序，与是否配置了乱序是两回事，所以工具会为此计数：统计页上的**乱序包数**
（以及统计 CSV 中的 `packets_reordered`）。设置了尖峰而结果为 0，意味着你的流量太稀疏，
没有任何数据包能超过另一个，而不是设置被忽略了。该计数是按方向统计的，
所以两条繁忙的连接可以互相超越，而两端都看不到任何乱序。

**弱网效果**：*丢包*：数据包悄无声息消失的百分比（5% 已经是明显出故障的网络）。*数据损坏*：
数据位被翻转的数据包的百分比，它**只影响带有载荷的数据包**。没有数据的数据包
（例如纯 ACK、SYN）没有可翻转的内容，所以会原样通过，而且**不计入损坏**。*重复包*：被发送两次的数据包的百分比。

**连续丢包（burst）**：真实的链路很少一次只丢一个数据包。微波炉、电梯，
或者在不同发射机之间切换，都会让连接中断片刻，这一刻发出的一切都会丢失。
这个字段指定平均有多少数据包会**连续**丢失，而*丢包*仍然决定总共丢多少。
它比看上去更重要：分散的 5% 丢包，大多数连接都能吸收，
而成串二十个的同样 5% 丢包，会让传输停滞，打断实时连接，并把应用推上重连的路径。
设为 0 表示均匀分散丢包，这就是这项设置出现之前工具的做法。

有两个值得了解的限制，应用设置时日志会把两者都说明。极高的丢包率无法以很短的串出现，
因为串太短，彼此之间留不出足够的间隔，所以日志会说明这次运行实际会达到多少。
而较长的串长度会让各串相隔很远，所以较短的会话可能一个都遇不到。每个方向都有各自的串，
所以串长为二十，就表示该方向上连续二十个，开启“非对称”时，日志也会给出上传的两个限制。
在 100% 丢包时，每个数据包都会丢失，所以串长不起任何作用。

**链路时通时断**：周期性的全部流量丢失：每隔*周期*秒，链路会在给定百分比的时间内处于中断状态。
它模拟闪断的连接。这与连续丢包**不同**：链路时通时断是可以预测的固定周期，
而上面说的串是随机的，夹在其他正常的流量中间，而且很短。

**高级（NAT / 连接）：**
- *目标地址（IP/端口）*：只对往返于所选服务器的流量施加影响。两个字段都接受列表、范围、CIDR、通配符、
  比较、排除和正则表达式，详见[过滤语法](#过滤语法进程--ip--端口)。例如 IP `10.0.0.1-10.0.0.50,!10.0.0.7`，
  端口 `80,443,8000-8100`。留空 = 任意。
- *丢弃 TCP SYN（%）*：被丢弃的建立连接数据包的百分比。模拟无法建立的连接（用于重试测试），
  对在 NAT 之后进行的测试很有用。
- *最大大小（MTU）*：丢弃大于 N 字节的数据包。重现来自隧道/VPN/NAT 之后的“MTU 黑洞”
  （小包能通过，大包消失）。0 = 禁用。
- *NAT 超时*：如果一条连接静默超过 N 秒，下一个入站数据包会被丢弃（映射“消失”）。
  用于保活测试。0 = 禁用。
- *TCP 重置（RST）*：被 RST 数据包突然中断的连接的百分比。会强制重连。**仅限 TCP**
  （RST 是 TCP 的概念，UDP 无法被“中断”，请使用丢包或链路时通时断）。
  **立即重置 TCP** 按钮会把所有活动的 TCP 连接重置约 3 秒。
- *计划*：随时间变化的吞吐量：`time:download:upload`，单位 KB/s，以逗号分隔。
  例如 `2:100:0, 2:500:0` = 2 秒保持 100 KB/s，然后 2 秒 500，循环往复。
  计划非空时，它会**覆盖**固定的“下载/上传”字段，图形界面会把它们变灰，并明确说明。
  一个步骤的时间要大于 0 且不超过 86400 秒，每个速度从 0（不限制）到 10000000 KB/s，与固定字段一样。
  超出这个范围的步骤会被拒绝，并指出是哪一步。

**会话：**
- *运行时长（秒）*：经过这么多秒后，程序会**自行停止**（和你点击停止完全一样）：弱网影响消失，驱动被释放。
  `0` = 一直运行到停止（以前的默认行为）。CLI 中对应的是 `--duration`。与流量过滤器一样，
  它**只在开始时**被采纳（“应用更改”不会改动它）。该值会保存在配置文件和复现命令中。

**可重复性与场景：**
- *随机种子*：设置任意一个数字，每次运行的随机化就会相同（bug 因此可以复现）。留空 = 每次都不同。
  **只在开始时**采纳，所以会话运行期间它是锁定的。
- *场景*：一个在运行时实时改变设置的 JSON 文件（例如 10 秒后增加 ping，20 秒后切断连接）。
  “循环”会无休止地重放它。示例在 `scenarios/` 中（咖啡馆 Wi-Fi、移动 LTE->3G、
  拥堵的 VPN、故障的 DNS、过载的游戏服务器、上传中途中断、被阻断的后端/API）。
  “加载场景...”“清空”和“循环”在开始时生效，所以会话运行期间它们是锁定的。
  场景运行期间点击“应用更改”是可以的：见[场景文件格式](#场景文件格式)。

**配置方案**：现成的预设，**按从好（上）到差（下）排序**：完美网络、良好 Wi-Fi、5G 网络、
家庭 DSL（VDSL）、LTE / 4G、卫星网络（低轨）、远距离服务器（另一大洲）、弱 Wi-Fi、咖啡馆（拥挤 Wi-Fi）、
拥塞的家庭网络（缓冲膨胀）、火车 / 地铁（隧道）、3G 网络、国际漫游、卫星网络（地球同步轨道）、
机上 Wi-Fi、56k 调制解调器、极差网络，外加你自己的（以某个名称保存）。程序**总是从“完美网络”开始**
（在你设置之前，什么都不会受到影响）。内置预设无法删除，它们的“删除”按钮是禁用的。

无线类的预设丢包也是**成串**出现，而不是一次一个数据包，因为无线链路就是这样的：
信号衰落、干扰和切换会让信道中断一阵子。有线类的（DSL、56k 调制解调器）丢包则均匀分散，
因为那里的丢包是队列已满，而不是无线电信号消失。

它们的数值只要有公开的测量数据，就取自这些数据（卫星和移动网络取 Ookla® Speedtest® 的中位数，
Starlink 15 秒重配置、机上 Wi-Fi 以及 Wi-Fi 数据包连续丢失个数则取自经过同行评审的研究）。
每个数字的出处都写在 `beantester/presets.py` 顶部的注释块里，附有作者、发表场所和 DOI，
所以你可以核实，而不必轻信。没有这类数据的地方（“弱 Wi-Fi”不是一个可测量的量），
数值旁边的注释会如实说明，而不是捏造一个来源。其中几个值得多说一句：

- **卫星网络（低轨）**：以 Starlink 为模型。它的稳态很好（约 40 ms 的 ping，100 Mbit/s）。
  它与众不同之处在于每 15 秒一次的重新配置，会短暂中断传输，表现为偶发的延迟尖峰，而不是丢包。
- **远距离服务器（另一大洲）**：一条没有任何故障的快速链路，只是距离遥远（约 120 ms 的 ping）。
  它能暴露那些话痨式的协议，以及假定服务器就在隔壁的代码。
- **拥塞的家庭网络（缓冲膨胀）**：空闲时看起来没问题（20 ms 的 ping）。弱网效果在于队列。
  ⚠️ **只有当你的应用真正把链路跑满时它才会起作用**，因为缓冲区是限速器的一部分：
  发送一点点测试流量，你只会看到一条普通的 8 Mbit/s 下行、1 Mbit/s 上行的链路，别无其他。
  把 1 Mbit/s 的上行跑满，再看 ping 朝两秒攀升，这就是“有人开始备份时视频通话就崩了”的情形。
- **火车 / 地铁（隧道）**：唯一会让链路完全中断数秒的预设（每 30 秒中断 3 秒），
  所以应用必须**重新连接**，而不仅仅是变慢。
- **机上 Wi-Fi**：经典的卫星类型：约 750 ms 的 ping 和 7% 的丢包，这是实测的中位数，而不是最坏情况。
  装有较新低轨设备的飞机，表现则像“卫星网络（低轨）”。

配置方案保存的是**链路的特征**：丢包、连续到达的丢包有多少、数据损坏、重复、延迟、抖动、延迟尖峰、
链路中断（时通时断）、限速和缓冲区。其他一切，包括目标、目标地址、阻断、RST、MTU、NAT 过期、计划、随机种子，
都不在其中。保存配置方案时，会就你当前开启的这些项目给出警告。要保存完整配置，请使用“**保存文件...**”。
选择配置方案或预设时，会一次性设置**所有**这些字段，包括某个预设没有提到的字段，
它们会回到默认值，所以“完美网络”真的就是完美。早期版本保存的配置方案原样加载。

在 CLI（`--preset`）中，预设可以用它的**规范 id** 或**任何界面语言中的名称**来指定
（不区分大小写，也不区分波兰语变音符号，`"Perfect network"` 同样可用）。id 有：
`presets.perfect`、`presets.good_wifi`、`presets.5g`、`presets.dsl`、`presets.lte`、`presets.leo`、
`presets.distant`、`presets.weak_wifi`、`presets.cafe`、`presets.bufferbloat`、`presets.metro`、
`presets.3g`、`presets.roaming`、`presets.satellite`、`presets.inflight`、`presets.modem56k`、
`presets.terrible`。

## 过滤语法（进程 / IP / 端口）

三个字段，即**目标进程**、**IP** 和**端口**（位于“目标地址筛选”），使用同一种迷你语言。
工具今后新增的每一个过滤字段，也都会使用这套语法。它在图形界面和 CLI 中的行为完全一致
（`--target`、`--dst-ip`、`--dst-port`）。

### 基本构件

| 写法 | 含义 | 示例 |
|---|---|---|
| `a,b,c` | **列表**：匹配其中任意一个值 | `80,443` |
| `a-b` | **范围**，两端都**包含在内** | `8000-8100`、`10.0.0.1-10.0.0.50` |
| `>` `<` `>=` `<=` | **比较**（数值比较，IP 按地址的数值比较） | `>1024`、`<=80`、`>10.0.0.5` |
| `!` | **排除**：“不等于” | `!53` |
| `*` `?` | **通配符**（`*` = 任意一串字符，`?` = 单个字符） | `chrome*`、`192.168.1.*` |
| `re:` | **正则表达式**（Python `re`，不区分大小写） | `re:^chrome\.exe$` |
| `x.x.x.x/n` | **CIDR**（仅限 IP 字段） | `192.168.1.0/24`、`2001:db8::/32` |

字段为空 = **全部**（不过滤）。逗号和各项周围的空格会被忽略。

### 各项如何组合

```
matches = (no positive terms OR any positive term matches) AND no "!" term matches
```

换句话说：**正向项相加（OR），排除项相减（AND NOT）**。各项的顺序无关紧要：
`80,!53` 与 `!53,80` 的意思完全相同。

| 输入 | 含义 |
|---|---|
| *（空）* | 全部 |
| `443` | 仅端口 443 |
| `80,443` | 仅 80 **或** 443 |
| `!53` | **除 53 以外的全部**（没有正向项） |
| `!53,!443` | 除 53 和 443 以外的全部 |
| `1000-2000,!1500` | 1000-2000，但不含 1500 |
| `>1024,!3389` | 大于 1024 的全部，但不含 3389 |
| `80,443,8000-8100,>9000,!8080` | 80、443、8000-8100 以及大于 9000 的全部，8080 除外 |

### “目标进程”字段

一项可以是**名称**或 **PID**，可以在一个字段里混用。

* **名称**（不含 `*`，也不含 `re:`）按**不区分大小写的子串**匹配：`chrome`
  会匹配 `chrome.exe` **和** `chromedriver.exe`。（一直都是这样工作的，有意保留，
  这样旧的配置和配置方案仍然可用。）
* **PID**：一个纯数字（`12345`）、一个范围（`1000-2000`）或一个比较（`>1000`）。
* **通配符**和 **`re:`** 匹配进程的**名称**。
* 比较符 `>` `<` `>=` `<=` 只对 **PID**（数字）有意义。`>chrome` 是**错误**，
  工具会明确指出，而不是悄悄地什么都不匹配。

```
chrome.exe                     all processes with "chrome.exe" in the name
chrome, !chromedriver          chrome but NOT chromedriver
chrome.exe, firefox.exe        two apps at once
12345                          a specific PID
12345, 6789                    two PIDs
1000-2000                      all processes with a PID in that range
>1000                          all processes with a PID > 1000
firefox*                       a name starting with "firefox"
re:^(chrome|firefox)\.exe$      exactly chrome.exe or firefox.exe
firefox, 12345                 a name and a PID in one field
```

所有匹配的进程都会贡献它们的本地端口，定位范围覆盖这些端口的**并集**。
端口集合在会话期间根据系统的套接字事件持续更新，所以进程新打开的连接在打开时就会被捕获
（没有真正的 WinDivert 时，会退回到每秒数次重新扫描套接字表）。

**“它的本地端口”在实践中是什么意思。** 数据包携带的是地址和端口，从来不带程序名，
所以工具无法直接按“Chrome”来匹配。它会查出这个进程拥有哪些**本地**端口，
然后匹配本地端口上的每一个数据包。

这就是为什么这里从来看不到 `443`。Chrome 加载页面时，`443` 是**服务器**的端口，
Chrome 这一端使用的是 `15597` 这样的临时端口，而这个号码同一时刻只属于一个进程，
所以它的流量可以被精确捕获。

有少数端口的工作方式不同。mDNS（5353）、SSDP（1900）和 DHCP（67/68）由多个程序同时持有，
因为程序就是这样发现你网络上的设备的。在这些端口上，端口号不再说明流量属于谁，
所以只能全有或全无：要么该端口上的一切都受影响，要么一律不受影响。
发生这种情况时日志会说明，并指出适用的是两者中的哪一种。普通流量不受影响。

### “IP”字段

同时支持 **IPv4 和 IPv6**。规则永远不会匹配另一个地址族的地址：IPv4 规则不会捕获 IPv6 地址，
反之亦然（可以放心地在一个字段中混用两者）。

```
1.2.3.4                        one address
1.2.3.4, 8.8.8.8               two addresses
10.0.0.1-10.0.0.50             a range (both ends inclusive)
10.0.0.1-10.0.0.50, !10.0.0.7  a range with a hole
192.168.1.0/24                 a whole subnet (CIDR)
192.168.1.*                    the same via wildcard
!8.8.8.8                       everything except 8.8.8.8
>10.0.0.5                      addresses "greater" than 10.0.0.5
2001:db8::/32                  an IPv6 subnet
2001:db8::1-2001:db8::ff       an IPv6 range
10.0.0.0/8, 2001:db8::/32      IPv4 and IPv6 in one field
re:^10\.                        anything starting with 10.
```

地址的写法无关紧要：`2001:0db8:0000:0000:0000:0000:0000:0001` 和 `2001:db8::1`
在工具看来是同一个地址。

### “端口”字段

```
443                            one port
80,443                         a list
8000-8100                      a range (both ends inclusive)
>1024                          high ports
<=1024                         privileged ports
!53                            everything except DNS
80,443,8000-8100,!8080         a mix
```

允许的范围是 **0-65535**。`99999` 是错误，不会被悄悄跳过。

### 正则表达式（`re:`）

`re:` 前缀是**必须**的，没有它，一项就只是普通的值。这样 `chrome.exe` 就是文件名
（点就是点），而不是正则模式。

| 模式 | 匹配 |
|---|---|
| `re:^chrome` | 以 `chrome` 开头的名称 |
| `re:^chrome\.exe$` | **恰好是** `chrome.exe`（不含 `chromedriver.exe`） |
| `re:^(chrome\|firefox)\.exe$` | 恰好是 `chrome.exe` 或 `firefox.exe` |
| `re:(node\|python)` | 包含 `node` 或 `python` 的名称 |
| `re:^\d+$` | （在端口/PID 字段中）纯数字 |
| `re:^10\.` | （在 IP 字段中）以 `10.` 开头的地址 |
| `!re:^chrome` | **除了**以 `chrome` 开头的名称之外的全部 |

模式**不区分大小写**，并且在任意位置查找匹配（`re.search`）。如果你想要从头到尾完全匹配，
请使用 `^` 和 `$`。

**正则表达式内部的逗号必须用反斜杠转义**（`\,`），因为逗号是各项之间的分隔符：

```
re:^ch.{1\,8}e\.exe$          correct - {1,8} with a backslash before the comma
re:^ch.{1,8}e\.exe$           WRONG - it is split into "re:^ch.{1" and "8}e\.exe$"
```

### 容易踩坑的情况

* **`chrome` 也会捕获 `chromedriver`，但 `chrome.exe` 不会。** 单独的名称是一个*子串*：
  “chrome”这段文字出现在 `chromedriver.exe` 中，而“chrome.exe”这段文字没有
  （那里是 `chrome` + `driver.exe`）。所以 `chrome.exe` -> 只匹配 `chrome.exe`。`chrome` -> `chrome.exe`
  **和** `chromedriver.exe`。
* **`chrome*` 比看上去的范围更宽。** 星号表示“任意一串字符”，所以 `chrome*` 捕获
  `chromedriver.exe` 的方式与 `chrome` 完全一样。只想要某一个应用？请使用 `re:^chrome\.exe$`，
  或者加一个排除项：`chrome, !chromedriver`。
* **端口字段里的 `8*` 是对数字文本的通配符**，所以它会匹配 `8`、`80`、`8080` 和 `8443`，
  但**不会**匹配 `443`。你几乎肯定想要的是范围：`8000-8999`。请有意识地使用端口通配符。
* **`80,443,!8080` 就是 `80,443`。** 什么也没排除掉的排除项不算错误，只是没用。
* **`!53` 也会覆盖没有端口的流量**（例如 ICMP/ping）。“除 53 以外的全部”字面上就是
  “凡不是端口 53 的一切”，而 ICMP 数据包不是端口 53。如果你只想要 TCP/UDP，请缩小**流量过滤器**的范围。
* **空项是错误**，而不是“全部”：`80,,443` 和 `80,!` 会被拒绝。**整个字段**为空则表示“全部”。
* **IP 和端口以 AND 组合。** `IP=10.0.0.0/8` + `port=443` 表示“流向 10.x 网络的流量，
  **并且同时**在端口 443 上”。想要“二选一”？请把另一个字段留空，分两次运行。
* **`>chrome` 是错误。** 比较作用于数字（PID），而不是名称。
* **`2000-1000` 是错误**（范围反了），而不是空集。
* **通配符不是正则。** 在 `chrome*` 中，星号表示“任意一串字符”。在 `re:chrome*` 中，
  它表示“字母 `e` 重复 0 次或多次”。只要你写了 `re:`，写的就是正则表达式。
* **重复中套重复会被当作太慢而拒绝**，例如 `re:^(\w+)+$` 或 `re:^([0-9:]+)+$`。
  这样的模式遇到一个几乎匹配的名称或地址，可能要花上数秒，而地址是对每个数据包都要检查的。
  请只写一层重复：`re:^\w+$`。

每个语法错误都会被**立即**报告：在图形界面中，字段变红，原因（使用界面语言）显示在下方，
CLI 则以一条可读的 `error: ...` 结束，绝不会无声地“什么都不起作用”。

## 统计（计数器的含义）

吞吐量图表有带数值的 Y 轴（KB/s）、网格线、“漂亮”取整的刻度，角落里还有当前的下载/上传读数。
下载/上传（KB/s 实时）、数据包（通过了多少）、队列中（正在等待，会随延迟/限速增长）、已丢弃、
丢包串数（这些丢包是以多少**串**到来的，见“连续丢包”）、已损坏、已重复、缓冲区溢出（工具过载时丢弃）、
停止时丢弃（按下停止时仍在队列中的）、发送失败（工具捕获了它们，但无法放回线路：连接断了，或者驱动拒绝了）、
因限速丢弃（被已满的限速缓冲区丢弃，与丢包和“缓冲区溢出”分开计数）、SYN 已丢弃、因 MTU 丢弃、NAT 已过期、
RST 重置、局域网模式：互联网被切断、本地网络被切断、已发送 RST。

**复制数据。** 在“实时”或“会话”页上右键点击任意一个值，可以复制该值或整个选项卡。
每个面板还有一个按钮，网格下方的“复制计数器”和复现按钮旁边的“复制会话详情”，
它们会按屏幕上显示的样子复制每一行，包括标题和单位。写 bug 报告时很方便：
会话面板里有计算机名、它的地址、随机种子，以及捕获范围覆盖了什么。

其中最后三项，即“缓冲区溢出”“停止时丢弃”和“发送失败”，是工具丢了你的数据包，
而不是你要它模拟的链路造成的。它们会被计数，让已见/已送达/已丢弃的算术保持诚实，
并且特意**不**计入“有效丢失率”。其中任何一个不为零，都意味着你所测得的丢失中有一部分是我们造成的。

### 复现 bug（“会话与复现”面板）

这样设计，是为了在出现 bug 后，能够重现完全相同的条件：

- **实际随机种子**：即使你把随机种子字段留空，程序也会抽取并记住一个具体的种子。
  之后把它填进随机种子字段并再次运行，就能得到相同的抽取结果。
- **可重复的时通时断**：链路中断的模式从会话开始时起算，所以在相同设置下，每次运行都会完全一样地重复
  （它不依赖系统时钟）。
- **随机种子能复现什么**：种子复现的是引擎的**决定**（哪些数据包被丢弃、损坏、重复，延迟了多少），
  而不是**数据包的数量**。穿过链路的流量取决于你的应用和系统在那一刻做了什么，
  所以两次种子相同的运行，会得到相同的*比例*（例如两次都是 15.8% 的丢包），
  但计数器不会精确到每一个数据包都相同。在 CI 中做比较时，请使用比率（%），而不是原始的数据包数。
- **开始 / 持续时间 / 有效丢失率 / 队列峰值 / 下载/上传峰值**：这次运行的快速概览。
- **“有效丢失率”统计什么**：你所瞄准的流量中，被**这个工具**破坏的份额，涵盖**每一种**弱网效果：
  设置的丢包，加上限速丢弃、阻断、局域网切断、本地网络切断、链路中断、连接重置、SYN 丢弃、MTU 丢弃
  和 NAT 过期。设置了目标时，只统计目标的流量，所以其他应用无法稀释它。
  **工具**自己丢掉的数据包被特意排除在外：“缓冲区溢出”“停止时丢弃”和“发送失败”是它自己的失败，
  不是链路的，它们有各自的计数器。报告中的 `effective_loss_pct` 就是同一个数字，旁边是 `packets_in_scope`。
- **驱动队列等待（峰值）**：当本工具收到某个数据包时，它在 WinDivert 内部**已经**等待的最长时间。
  这是测量值，而不是估算：驱动给每个数据包打上捕获时间的戳，工具每秒对它采样 20 次。
  在空闲的机器上它只有零点几毫秒（这里实测：0.05-0.16 ms）。如果它增大，说明工具正在增加延迟，
  而这个延迟不会出现在其他任何计数器里，因为它发生在驱动的队列中，在工具自己的队列之前，
  一旦达到 50 ms，日志和事件列表中就会提示。在没有驱动的 `--simulate` 下为空。
- **它测量的是这台机器，而不是互联网。** 工具看到的是穿过这台电脑网络栈的数据包，
  所以在网络上丢失的数据包（永远没有回来的那个应答）永远不会到达这里，这里的任何东西也无法为它计数。
  一次干净的 30 个包的 ping，如果丢了一个应答，连接行上会显示 **59** 个数据包和 **0** 次丢弃，
  两个数字都是对的：发出了 30 个请求，回来了 29 个应答，而工具一个都没有破坏。
  端到端的丢失，要看你的应用自己的数据（或 `ping` 的“Lost”）。
- **已用数据量**：已下载 / 已上传 / 总计（MB），从开始起累计，外加会话的平均吞吐量。
  你马上就能知道应用用了多少数据。（报告中还有“尝试发送的 MB”，即应用在扣除丢包/限速之前想要发送的量。）
- **带时间戳的事件日志**：开始、设置更改、场景步骤、连接中断，以及你的故障标记，
  点击列标题即可**排序**。
- **标记故障时刻**：在你看到 bug 的那一刻点击。它会在日志中插入一个带时间戳的标记。
- **保存复现报告**：一个包含全部内容的 JSON 文件：随机种子、所有设置、计数器、指标、事件日志、
  连接，以及一条能重现这些条件的**现成 CLI 命令**。它还会记录**会话所处的 WinDivert 队列**
  （`session.driver_queue`：长度、时间和大小）。那是驱动自己的缓冲区，位于本工具的缓冲区之前，
  这三个值是上限，而不是固定的延迟：只要工具跟得上，数据包在其中几乎不用等待
  （见上文的**驱动队列等待（峰值）**）。只有当工具落后时它才会被填满。那时数据包等待得更久，
  队列一旦满了，驱动会在本工具看到数据包之前把它们丢掉。更小的队列并不能消除这种等待，
  只会把它变成任何计数器都显示不出来的丢包，所以工具不去动驱动自己的设置。
  来自一台你无法当面查看的机器的报告，会说明是哪个队列产生了它的数字。同样的三个值也会在开始时写入日志。
- **复制 CLI 命令**：直接复制到剪贴板：`BeanNetworkTester.exe --seed ... --loss ...
  --duration ...`（命令会适应构建方式：在源码仓库中得到的是
  `python bean_network_tester.py ...`）。
- **报告和命令描述的是什么**：上一次会话，而不是表单：开始时给它的设置，经每次“应用更改”更新，
  连同它的随机种子和它的场景（`--scenario`，如果循环过还有 `--loop`）。你输入了但没有应用的更改不会包含在内，
  停止之后加载的配置方案也不会。在场景期间，“应用更改”会成为之后各个步骤所依据的基础，
  所以命令也会采用这些设置。随程序提供的场景会以程序所在文件夹为起点命名
  （源码中是 `scenarios\...`，`.exe` 旁边是 `_internal\scenarios\...`），
  命令在你运行它的任何文件夹中都能找到它。其他任何文件，则以你选择的路径命名。
  在第一次会话之前，**复制 CLI 命令**复制的是表单中的设置。

## 配置文件

“保存/加载文件”按钮会把所有设置写入 JSON。同一个文件通过 `--config` 也可用于 CLI。
优先级顺序：默认值 < 文件 < 预设 < 参数。

读取文件时，每个值都会检查其类型，场景步骤也以同样的方式检查。开关
（`lan_mode`、`internet_only`、`narrow_filter`...）是 `true` 或 `false`，或者 `1` 或 `0`。
文本 `"false"` 会被拒绝，而不会被当作“开”。`filter` 是 `--filter` 的选项之一，
`seed` 是整数（`-1` 表示随机）。类型错误的值会让 CLI 以代码 `3` 停止，并指出是哪项设置。
窗口会显示同样的消息，并保持表单原样。

## 命令行模式（CLI）

CLI 与图形界面**使用同一个 `BeanNetworkTester.exe`**：带任意参数启动就进入文本模式
（没有窗口，不加载 tkinter），不带参数则进入图形界面。消息和 `--help` 始终是英语。

```bat
:: GUI
BeanNetworkTester.exe

:: CLI (from the same exe)
BeanNetworkTester.exe --loss 5 --latency 100 --down 1024 --target chrome.exe
BeanNetworkTester.exe --preset "3G network" --duration 60
```

> 在源码仓库中工作（没有构建）？请在所有地方把 `BeanNetworkTester.exe` 替换为
> `python bean_network_tester.py`，所有参数和退出码都完全相同。

### 退出码（CI/CD 约定）

每一种结束方式都有自己的代码，流水线不需要解析文本：

| 代码 | 名称 | 何时 |
|---|---|---|
| `0` | ok | 会话运行完毕，并且所有检查都通过 |
| `1` | runtime | 无法启动（没有 `pydivert`、驱动问题、引擎故障） |
| `2` | usage | 命令行有误（未知参数、类型错误），这是 argparse 的代码 |
| `3` | config | 设置无效：表达式、计划、范围、预设、配置文件 |
| `4` | scenario | 场景文件缺失或格式错误 |
| `5` | io | 无法写入某个产物（复现报告、保存的配置） |
| `6` | assertion | 运行成功，但 `--min-packets` / `--fail-on-no-traffic` 未通过 |
| `7` | permission | 需要管理员权限（Windows）或 root（Linux），但没有 |
| `130` | interrupted | Ctrl+C（SIGINT） |
| `143` | terminated | SIGTERM（作业取消、`docker stop`）、Ctrl+Break，或关闭控制台窗口 |

`BeanNetworkTester.exe --help` 会打印同样的代码。

### 输出：日志走 stderr，数据走 stdout

- **stderr**：给人看的日志，以 `[bean]` 为前缀（开始、随机种子、错误、停止原因）。
- **stdout**：数据，即报告行，使用 `--format json` 时则是 **NDJSON**（每行一个 JSON 对象：
  一连串的 `sample` 对象，最后是带有退出码、随机种子和复现命令的 `summary`）。

```bat
BeanNetworkTester.exe --simulate --duration 30 --format json > run.ndjson
```

### 全部 CLI 参数

**链路弱网**

| 参数 | 单位 | 说明 |
|---|---|---|
| `--loss` | % | 被丢弃的数据包的百分比 |
| `--loss-burst` | 个数据包 | 平均连续丢失的数据包个数（0 = 丢包均匀分散）。它决定 `--loss` 的形态，而不是在其上叠加 |
| `--corrupt` | % | 被翻转一位的数据包的百分比 |
| `--dup` | % | 被发送两次的数据包的百分比 |
| `--latency` | ms | 给每个数据包增加的固定延迟 |
| `--jitter` | ms | 延迟的随机变化（+/-） |
| `--down` `--up` | KB/s | 吞吐量限制（0 = 不限制） |
| `--buffer` | ms | 限速的链路缓冲区（0 = 不限制）。限制排队延迟，多余的部分计入“因限速丢弃” |
| `--spike-prob` `--spike-ms` | % / ms | 以给定的概率附加额外的延迟 |
| `--syn-drop` | % | 被丢弃的 TCP SYN 数据包的百分比 |
| `--max-size` | B | “MTU 黑洞”：丢弃大于 N 字节的数据包（0 = 关闭） |
| `--nat-timeout` | s | 静默 N 秒后，NAT 映射“消失”（0 = 关闭） |
| `--rst-prob` `--rst-cooldown` | % / s | 被 RST 中断的连接的百分比，以及中断保持多久 |
| `--flap-period` `--flap-down` | s / % | 周期性的链路中断：多久一次，以及占周期的多大比例 |
| `--rate-schedule` | - | 变化的吞吐量：`"time:download:upload,..."`，单位 KB/s，循环。时间要大于 0 且不超过 86400 秒，速度为 0（不限制）到 10000000 |
| `--asym` | - | 让上传使用自己的数值。不加它时，一组数字对两个方向都适用，这是默认行为 |
| `--loss-up` `--corrupt-up` `--dup-up` | % | 同样这三种弱网效果，用于这台机器所发送的数据包。仅与 `--asym` 一起使用 |
| `--latency-up` `--jitter-up` | ms | 延迟及其变化，用于这台机器所发送的数据包。仅与 `--asym` 一起使用 |
| `--spike-prob-up` `--spike-ms-up` | % / ms | 偶发的较长延迟，用于这台机器所发送的数据包。仅与 `--asym` 一起使用 |
| `--ipv4-only` `--ipv6-only` | - | 只对一个地址族施加影响。另一个照常畅通，不受影响，这是用来瞄准目标的，而不是阻断某个协议。`--dst-ip` 为空（即所有地址）时同样可用。两个参数同时给出会互相排斥，不会有任何东西受影响，日志会说明这一点 |
| `--lan-mode` | - | 局域网模式：切断互联网（公网地址），保留本地网络 |
| `--internet-only` | - | 与之相反：切断本地网络（10.x、172.16-31.x、192.168.x、链路本地、CGNAT），保留互联网。环回依旧可用。注意：向路由器查询 DNS 属于本地流量，所以互联网可能随之无法使用 |
| `--narrow-filter` | - | 把 `--dst-ip`/`--dst-port` 下推到 WinDivert 过滤器中，让驱动不再交出那些不可能受影响的流量（在高数据包速率下快得多）。仅在开始时生效。开启后，统计和连接只覆盖收窄后的流量 |

**目标定位**（三个参数都接受完整的[过滤语法](#过滤语法进程--ip--端口)：列表、
范围、`!`、`>`、`<`、`>=`、`<=`、通配符、`re:`，其中 `--dst-ip` 另外还支持 CIDR）

| 参数 | 说明 | 示例 |
|---|---|---|
| `--target` | 进程：名称、PID、PID 范围、通配符、正则 | `--target chrome.exe`<br>`--target "chrome,!chromedriver"`<br>`--target ">1000"` |
| `--dst-ip` | 远程 IP 地址（IPv4 和 IPv6） | `--dst-ip 1.2.3.4`<br>`--dst-ip "10.0.0.1-10.0.0.50,!10.0.0.7"`<br>`--dst-ip "192.168.1.0/24"`<br>`--dst-ip "2001:db8::/32"` |
| `--dst-port` | 远程端口（0-65535） | `--dst-port 443`<br>`--dst-port "80,443,8000-8100"`<br>`--dst-port "!53"`<br>`--dst-port ">1024"` |
| `--filter` | 到底捕获哪些流量（IPv4 + IPv6）：`both,out,in,tcp,udp,ping,loopback` | `--filter tcp` |

**阻断（防火墙）**：丢弃发往所选目标的所有流量。阻断由 **IP 或端口** 触发（空字段会被忽略，
所以单独的 `--block-port 443` 会阻断发往任何地址的 443）。与上面相同的[过滤语法](#过滤语法进程--ip--端口)。
它遵循进程定位（只阻断目标的流量）。

| 参数 | 说明 | 示例 |
|---|---|---|
| `--block-ip` | 阻断远程 IP 地址（IPv4 和 IPv6） | `--block-ip 1.2.3.4`<br>`--block-ip "10.0.0.0/8,!10.0.0.1"` |
| `--block-port` | 阻断远程端口（0-65535） | `--block-port 443`<br>`--block-port "80,443,8000-8100"` |
| `--block-reject` | 拒绝被阻断的 TCP 连接，而不是悄悄丢弃 | `--block-port 443 --block-reject` |

**拒绝还是忽略**：默认情况下，被阻断的连接完全得不到任何应答，被测程序会一直等到自己放弃。
使用 `--block-reject` 时，连接会被拒绝，程序大约两秒后就会报告“连接被拒绝”，
和访问一个真正关闭的端口时一样。这在大多数应用中是两条不同的代码路径，
而只见过其中一条的测试套件，也就只测试了其中一条。
拒绝只涵盖**这台电脑发起的、基于 TCP 的连接**：UDP 上的流量以及从外部进来的连接，仍然被悄悄阻断。

> 在 `cmd.exe`/PowerShell 中，如果表达式包含逗号、`!`、`>`、`<`、`*` 或 `^`，请**给表达式加引号**，
> 否则 shell 会按它自己的方式解释（`cmd.exe` 会丢掉单独的 `^`，所以 `re:^edge`
> 会变成 `re:edge`）。重现会话的命令（“复制 CLI 命令”按钮，英语界面中为 `Copy CLI command`，
> 以及 `Reproduce:` 那一行）会替你加好引号。

### 目标定位示例

```bat
:: only the browser, but not its test driver
BeanNetworkTester.exe --loss 10 --target "chrome,!chromedriver"

:: only HTTPS traffic to a test server and its backup address
BeanNetworkTester.exe --latency 300 --dst-ip "10.0.0.5,10.0.0.9" --dst-port 443

:: the whole test subnet except one host, on application ports
BeanNetworkTester.exe --down 128 --dst-ip "10.0.0.0/24,!10.0.0.1" --dst-port "8000-8100"

:: everything EXCEPT DNS (so name resolution works while the rest breaks)
BeanNetworkTester.exe --loss 20 --dst-port "!53"

:: high-PID processes, traffic to IPv6
BeanNetworkTester.exe --jitter 80 --target ">1000" --dst-ip "2001:db8::/32"
```

### 阻断示例（防火墙）

```bat
:: cut the app off from an external API (the server is "down")
BeanNetworkTester.exe --block-ip 203.0.113.10

:: block all HTTPS - see how the app copes with no connection
BeanNetworkTester.exe --block-port 443

:: block several ports OR the whole backend subnet (blocking is IP OR port)
BeanNetworkTester.exe --block-port "8080,9090" --block-ip 203.0.113.0/24

:: impair only your app's traffic, and cut its link to the payment server entirely
BeanNetworkTester.exe --latency 200 --target myapp.exe --block-ip 198.51.100.7
```

### `--simulate` 模式（无需 Windows 和管理员权限的测试）

在合成流量上预览，既不需要 WinDivert，也不需要特权：

```bat
BeanNetworkTester.exe --simulate --down 500 --loss 10 --duration 4 --interval 1
```

### 在 CLI 中实现可重复与场景

```bat
BeanNetworkTester.exe --simulate --seed 42 --loss 20 --duration 10
BeanNetworkTester.exe --simulate --scenario scenarios/cafe-wifi.json
```

`scenarios/<name>.json`（或 `_internal\scenarios\<name>.json`）可以从任何文件夹打开随程序提供的场景。
如果当前文件夹在该路径下有一个文件，则使用那个文件。

对于相同的数据包序列，随机种子保证**逐包决定**完全一致。场景步骤是累积的（每一步都在修改状态），
`action: reset_tcp` 会在那一刻中断 TCP 连接。场景文件在**打开时就会校验**：随便一个 JSON
会以一条可读的错误结束，而不是“0 个步骤的场景”，步骤中的设置按表单所用的同一规则检查，
所以程序无法使用的值会连同其步骤编号一起被指出，而不是让运行进行到一半才停下。

每次 CLI 运行结束时，都会打印出**实际使用的随机种子**和一条现成的复现命令，其中的
`--scenario` 文件按你输入的原样给出，运行带有 `--loop` 和 `--simulate` 时也会包含它们，
`--repro-out file.json` 则会用同一条命令保存完整的复现报告。

## 连接列

共十七列，都可以点击列标题排序，每个列标题上的工具提示里也有同样的说明。

| 列 | 内容 |
|---|---|
| `进程` | 拥有本地端口的进程。`?` 表示无法解析出名称，请以管理员身份运行。 |
| `PID` | 拥有本地端口的进程 ID，在捕获数据包时解析。 |
| `协议` | 传输协议：TCP / UDP / ICMP / IP。 |
| `远程 IP` | 这台机器正在与之通信的地址。右键点击某一行，可以把弱网影响限定在该地址上。 |
| `远程端口` | 远端的端口（443 = HTTPS，53 = DNS，80 = HTTP）。没有端口的流量（如 ping）为空。 |
| `本地端口` | 这台机器上的端口，也就是把连接与进程联系起来的东西。ping/ICMP 为空，这也是这些行通常没有进程名的原因。 |
| `数据包` | 这条连接出现以来看到的数据包数。 |
| `受影响？` | 这条连接在本次会话中是否**位于弱网作用范围内**：是被施加了影响，而不仅仅是被观察。连接关闭后它仍保持为“是”，作为记录。没有设置目标规则时，一切都在范围内。 |
| `已丢弃` | 这条连接上被当前生效的弱网效果（丢包、链路中断、局域网模式、“仅互联网”、重置等）丢弃的数据包数。 |
| `下载` | 实际**到达**应用的数据，即它下载到的内容。与会话面板中的“已下载（MB）”是同一个量。 |
| `上传` | 实际**离开**这台机器的数据，即应用上传出去的内容。 |
| `总计` | 已送达的下载 + 已送达的上传。 |
| `观测下载` | 工具在施加任何弱网影响之前**捕获**到的入站数据，即这条连接原本提供的内容。 |
| `观测上传` | 工具**捕获**到的出站数据，即应用试图发送的内容。 |
| `均值[B]` | 这条连接上数据包的平均大小（总字节数 / 数据包数）。 |
| `时长[s]` | 本次会话中，这条连接第一个与最后一个数据包之间相隔的秒数。 |
| `空闲[s]` | 距离最后一个数据包过去的秒数。会话停止后不再计时。 |

**五个流量列自带单位。** 每个单元格都用最合适的 B、KB、MB 或 GB 来显示，
所以 5 GB 的流量显示为 `5.00 GB`，而不是 `5242880.0`，一条九十字节的 DNS 应答显示为 `90 B`，
而不是 `0.0`。表格下方的页脚对它的合计也是这样处理的。`avg`（界面中的“均值[B]”）是数据包大小，仍以字节为单位。
排序和 CSV 导出不受影响，两者都基于原始字节数，而不是单元格里的文本。

**已送达/观测这一对，正是这张表的要点。** 没有施加任何弱网影响时，两者相等。加入丢包或限速后，
它们就会分开，**两者之间的差距就是这条连接受到的损害**。（拆分之前只有一对数值，
它放的是捕获到的字节数，列标题却表示已送达：一行可能显示收到 5 MB，而对应的应用实际只得到 0.4 MB。）

## CSV 导出

两个按钮写出两个文件，它们**有意采取不同的行为**。两者都保存在你自己的文件夹
`%LOCALAPPDATA%\BeanNetworkTester` 中，与配置方案和窗口状态放在一起（从源码运行时则在项目根目录）。
每次保存时，程序都会把完整路径写入日志。它们被放在程序文件夹之外，这样更新程序
（手动更新或通过包管理器，这会替换那个文件夹）就不会把你的文件带走。

如果想让这台机器上的所有帐户共用一个文件夹，管理员可以把 `BEAN_DATA_DIR` 设为系统级环境变量。

| 文件 | `bean_network_tester_stats.csv` | `bean_network_tester_connections.csv` |

统计 CSV 不遵循“仅显示目标流量”开关，因为它是一份追加日志：一个文件的列在某些行里表示一种含义，
在其余行里表示另一种含义，对它所服务的电子表格来说比没有还糟。它改为同时包含**两种**合计
（`bytes_in`/`bytes_out` 和 `delivered_in_scope_bytes_*`），所以你可以自己缩小范围，
同时仍能分清哪个是哪个。**“仅捕获目标流量”无法这样撤销**，因为它从一开始就改变了
`packets_seen` 统计的内容，所以每一行都在 `capture_narrowed` 中记录了它。

### 统计 CSV 列

`time`、会话的捕获范围，然后是每个计数器，按此顺序：

| 列 | 含义 |
|---|---|
| `time` | 点击时的挂钟时间 |
| `capture_narrowed` | 该会话生效的是“仅捕获目标流量”时为 `yes`，这样这一行上的每个计数都**只**涵盖你目标地址的流量。`no` 表示这一行涵盖流量过滤器放行的一切。没有这一列，两行 `packets_seen` 相同的数据可能描述完全不同的流量 |
| `packets_seen` | 捕获的数据包 |
| `packets_in_scope` | 其中被选为施加弱网影响的目标的数据包 |
| `dropped_loss` | 被“丢包”设置丢弃的 |
| `loss_runs` | 这些丢包是以多少**串**到来的（见“连续丢包”）。设置了串长而结果为 0，意味着会话太短，没遇到过一串，或者丢包率是 100%，不存在单独的串 |
| `dropped_overflow` | 因工具自己的队列已满而丢弃的（见下文对它的说明） |
| `corrupted` | 载荷被翻转的数据包 |
| `duplicated` | 额外排入队列的副本 |
| `packets_reordered` | 离开工具时的顺序与进入时不同的数据包。配置了抖动或尖峰而结果为 0，意味着数据包之间相隔太远，没有任何一个能超越另一个。按方向统计，所以两条繁忙的连接可以互相超越，而两端都看不到任何乱序 |
| `dropped_syn` | 被丢弃的 TCP SYN（“永远打不开的连接”） |
| `dropped_mtu` | 因超过最大大小而丢弃的（MTU 黑洞） |
| `dropped_nat` | 因 NAT 映射已过期而丢弃的 |
| `dropped_rst` | 连接在重置后被压制期间吞掉的流量 |
| `dropped_lan` | 被局域网模式丢弃的（互联网被切断，本地网络正常） |
| `dropped_local_network` | 被“仅互联网”丢弃的（本地网络被切断，互联网和环回正常） |
| `dropped_block` | 被阻断（防火墙）字段丢弃的 |
| `dropped_link_outage` | 在时通时断的中断期间丢弃的 |
| `dropped_rate_limit` | 被已满的限速缓冲区丢弃的 |
| `dropped_at_stop` | 会话停止时被丢弃的、仍在队列中的数据包 |
| `dropped_send_failed` | 驱动拒绝重新注入的 |
| `connections_reset` | 实际被中断的连接 |
| `connections_refused` | 被拒绝而不是被忽略的、被阻断的连接（`--block-reject`） |
| `rst_sent` | 到达协议栈的 RST 数据包 |
| `bytes_in` / `bytes_out` | 已送达的字节数，所有捕获的流量 |
| `bytes_in_total` / `bytes_out_total` | 捕获的字节数，在施加弱网影响之前 |
| `delivered_in_scope_bytes_down` / `delivered_in_scope_bytes_up` | 已送达的字节数，仅目标流量 |
| `queue_len` / `queue_peak` | 在延迟队列中等待的数据包数，当前值和峰值 |
| `driver_wait_peak_ms` | 驱动让一个数据包在工具看到它之前等待的最长时间，从工具开始读取之后计算（开始仍在准备时捕获的数据包不计入） |

最后三个丢弃计数器，即 `dropped_overflow`、`dropped_at_stop`、`dropped_send_failed`，
是**工具自己**的损失，而不是你要求施加的弱网效果，因此它们被单独计数。

## 场景文件格式

场景是一条时间线：一个步骤列表，每一步都有以秒为单位的时间，以及在那一刻要做什么。
文件是 JSON，可以是一个对象，也可以是一个单纯的步骤列表：

```json
{
  "loop": true,
  "steps": [
    { "at": 0,  "settings": { "latency": 20, "jitter": 15, "loss": 1, "down": 1024, "up": 256 } },
    { "at": 20, "settings": { "loss": 3, "down": 512 } },
    { "at": 45, "action": "reset_tcp", "duration": 5 },
    { "at": 60, "settings": { "loss": 0, "flap_period": 0 } }
  ]
}
```

**文件层级**

| 键 | 含义 |
|---|---|
| `steps` | 必需，步骤列表。顶层直接写一个 `[ ... ]` 也可以，其含义是 `loop: false`。 |
| `loop` | 可选，默认 `false`。无休止地重放时间线，在最后一步的 `at` 之后重新开始。最后一步的设置和动作恰好在每次重新开始之前应用，所以在循环中它只持续一瞬间。想让最后一个阶段持续下去，请再加一个更晚的步骤。 |

**场景运行期间的“应用更改”**：它会立即生效，之后的每一步都建立在它之上，而不是建立在开始时
给会话的设置之上。没有任何步骤触及的设置（目标进程、目标地址的定位）会把它的新值保持到最后。
步骤中设置过的设置，只在下一步之前保持新值，下一步会把场景中的值放回去。

**步骤层级**：一个步骤需要 `settings`、`action`，或者两者都有。两者都没有的步骤是错误，而不是暂停。

| 键 | 含义 |
|---|---|
| `at` | 必需，距会话开始的秒数（`>= 0`）。步骤会按它排序，所以它们在文件中的顺序无关紧要。 |
| `settings` | 一个**局部的**设置对象。**累积**：每一步都在前面各步留下的状态上打补丁，所以一个值会一直保持，直到后面某一步把它改回去。 |
| `action` | `reset_tcp`：中断那一刻范围内的 TCP 连接。**这是唯一的动作。** 1.3 之前的写法 `reset_now` 已被移除，所以仍在使用它的文件会加载失败，并给出指出该步骤的消息。 |
| `duration` | 重置使连接保持中断的秒数（默认 `3`），要大于 0 且不超过 3600。只有与 `action` 一起才有效。 |

**`settings` 中可以写哪些名称**：工具拥有的任何设置，使用与**配置文件相同的名称**
（也就是它的命令行参数，把短横线换成下划线）：`loss`、`latency`、`jitter`、
`down`、`up`、`buffer`、`spike_prob`、`flap_period`、`dst_ip`、`block_port`、`target`、
`rate_schedule`、`max_size`、`nat_timeout`、`rst_prob`、`lan_mode`、`internet_only` 以及
其余的。运行
`--print-config` 可以导出完整的名称集合及其当前值。步骤不能改变
`filter`、`duration`、`narrow_filter`、`row_limit` 或 `seed`：会话只在开始时采纳前三者
和 `seed`，而 `row_limit` 只有窗口中的表格会读取，引擎从不读取。设置其中任何一个的步骤什么也不会改变，
文件仍会加载，并且会说明这一点。

**所有内容都在文件加载时校验，每个错误都会指出自己。** 未知的设置、未知的动作、未知的键、
不是数字的 `duration`、什么也不做的步骤、为空或超过 **1000** 个步骤的步骤列表，
每一种都会失败，并给出指向步骤编号的消息。这比听上去更重要：拼错的键以前是**无声**的，
`"duraton"` 会悄悄让重置保持 3 秒的默认值，`"lop"` 会悄悄关掉循环，
这两种情况下，工具看上去都像是在无视这个文件。

步骤由一个**每 0.1 秒**触发一次的定时器应用，所以亚秒级的时间大约精确到这个程度。
`--dry-run` 无需触碰驱动就能校验 `--scenario`，这使它成为流水线中一项廉价的检查。

### `scenarios/` 中随程序提供的场景

除 `upload-drop-midway.json` 外都会循环，所以你可以启动一个然后放着不管。

| 文件 | 重现的内容 |
|---|---|
| `cafe-wifi.json` | 咖啡馆在 85 秒内逐渐坐满：一条还不错的链路恶化到约 240 ms 的 ping、6% 的丢包和 2 Mbit/s，在最糟糕的时刻，连接每 12 秒完全中断一次，然后恢复。 |
| `mobile-lte-to-3g.json` | 手机走出 LTE 覆盖范围：从 33 Mbit/s 的下行降到 3G 的 0.8，然后在 60 秒时**完全中断并伴随 TCP 重置**，接着部分恢复，再回到 LTE。用来测试网络在请求进行到一半时死掉，你的应用会怎么做。 |
| `congested-vpn.json` | 一条**上传**崩溃而下载依然正常的 VPN（512 降到 160 KB/s），带有延迟尖峰、1400 的 MTU 和偶发的重置。 |
| `failing-dns.json` | **仅瞄准端口 53**（DNS，想放过基于 TCP 的 DNS，请在开始前把过滤器设为“仅 UDP”）：名称解析退化到 60% 的丢包和 1.5 秒的 ping，**完全失效 13 秒**，然后恢复。机器上的其他一切照常工作，这就是它成为 DNS 测试而不是中断测试的原因。 |
| `overloaded-game-server.json` | 一台在负载下不堪重负的服务器：ping、抖动、丢包和重复一起攀升，45% 的数据包带有最高 800 ms 的延迟尖峰。 |
| `same-loss-in-runs.json` | 整个运行期间都是同样的 5% 丢包，但以四种不同的方式到来：均匀分散，然后是每串 5、15 和 40 个数据包。其他一切都不变，所以出问题的是丢包的**形态**，而不是丢了多少。用来检验你的重连路径是否可用。 |
| `upload-drop-midway.json` | **不循环**，是一次性的：一次起初正常的上传先逐渐恶化，然后在传输途中**被切断为零**并伴随 TCP 重置，之后部分恢复。用来测试可续传的上传，以及会说谎的进度条。 |
| `blocked-endpoint.json` | 一个后端（`203.0.113.0/24`）在 20 秒时被**阻断**，其他一切继续工作，之后解除阻断。用来测试针对单个依赖项的超时、重试和回退。 |

## CI/CD 示例

### 1. 在 E2E 测试的后台模拟链路劣化（GitHub Actions，Windows）

测试在 300 ms 延迟和 5% 丢包下运行。整形器会在 120 秒后自行停止，所以不会有“卡住”的步骤
在代理机上留下一个被破坏的网络。

```yaml
- name: Start the network shaper (background, self-stopping)
  shell: pwsh
  run: |
    $p = Start-Process -FilePath dist\BeanNetworkTester\BeanNetworkTester.exe `
      -ArgumentList '--latency','300','--loss','5','--duration','120',
                    '--dst-port','443','--fail-on-no-traffic',
                    '--format','json','--log-file','shaper.log' `
      -RedirectStandardOutput shaper.ndjson -PassThru
    "SHAPER_PID=$($p.Id)" >> $env:GITHUB_ENV

- name: Run the E2E suite under bad network
  run: npm run test:e2e

- name: Stop the shaper and check it actually impaired something
  if: always()
  shell: pwsh
  run: |
    Stop-Process -Id $env:SHAPER_PID -ErrorAction SilentlyContinue
    Get-Content shaper.ndjson | Select-Object -Last 1
```

> **注意：** 请带着 `--duration` 运行后台进程，它是安全网。即使“停止”步骤从未运行
> （作业取消、超时），会话也会自行关闭，驱动被释放，代理机会恢复正常的网络。

### 2. 在 pre-commit / PR 中校验配置（无需驱动，无需管理员权限）

```bat
BeanNetworkTester.exe --dry-run --config profiles/bad-3g.json
```
代码 `0` = 文件有效。`3` = 有错误（stderr 上有可读的消息）。拼错的设置也算错误，并会指出是哪个键。
它以前会被无声地丢弃，于是检查通过了，而运行时却是在缺少这项设置的情况下进行的。

`--dry-run` 检查的是**设置**，而不是机器：它从不询问管理员权限或驱动，
所以在一台实际上无法执行捕获的构建代理机上，它也会返回 `0`。这是有意为之：在一处校验配置，
在另一处运行它，是很正常的事。当你想两方面都得到答案时，请运行这一对命令：

```bat
BeanNetworkTester.exe --doctor && BeanNetworkTester.exe --dry-run --config profiles/bad-3g.json
```

### 3. 带产物的、简短而可重复的运行

```bat
BeanNetworkTester.exe --preset presets.3g --seed 42 --duration 60 ^
  --repro-out repro.json --format json --fail-on-no-traffic > run.ndjson
```
这些产物（`run.ndjson`、`repro.json`）足以 1:1 重现这些条件，`repro.json` 里包含一条现成的 `cli_command`。

### 4. 清理代理机环境

```bat
BeanNetworkTester.exe --doctor
BeanNetworkTester.exe --cleanup-driver
```

## 构建 .exe

在 Windows 上：

```bat
pip install pyinstaller pydivert psutil
pyinstaller --noconfirm BeanNetworkTester.spec
```

结果：**`dist\BeanNetworkTester\BeanNetworkTester.exe`**（一个目录，里面有 exe、WinDivert 驱动、翻译和图标）。
这一个文件**同时运行图形界面和 CLI**。

三个有意为之的构建决定（没有必要请不要改动，每一个都修复了一个真实的 bug）：

- **控制台子系统**（不是 `--noconsole`）：否则 exe 没有 `stdout`/`stderr`，
  而 `cmd.exe` 和 PowerShell **不会等待**图形界面进程，CI 既看不到输出，也看不到退出码。
  图形界面启动时，程序会自己与控制台分离，所以双击不会留下黑色窗口。
- **onedir**（不是 `--onefile`）：`pydivert` 自带 `WinDivert64.sys`，而 onefile 会把它解压到
  `%TEMP%\_MEIxxxx`。内核持有已加载的 `.sys` 的打开句柄，所以该目录在重启之前**无法删除**。
  在目录构建中，驱动位于 exe 旁边，路径稳定。
- **`asInvoker`**（不是 `--uac-admin`）：`requireAdministrator` 在提权时总是会创建一个**新**进程，
  从而丢失调用方的管道和退出码。现在由图形界面自己请求提权，
  而 CLI 在缺少权限时以代码 `7` 和一条清晰的消息结束（`--simulate` 不需要权限）。

图标可以用 Pillow 脚本重新生成（`pip install pillow`），但正常运行并不需要 Pillow。

## 常见陷阱（提交 bug 前请阅读）

- **`--duration` 是安全网，而不只是为了方便。** 没有它，会话会一直持续到 `Ctrl+C` / 停止。
  在 CI 中**请务必**带上 `--duration`。唯一的例外是带时间线的场景：
  `--scenario` 指向一个不循环且多于一个步骤的文件时，现在会在场景结束时结束运行，并在开始时说明这一点。
  循环的或只有单个步骤的场景没有可停止的终点，所以它会发出警告并一直运行，直到你停止它。
- **关闭控制台窗口会干净地停止运行，注销则不会。** 关闭控制台窗口，会像 Ctrl+Break 一样结束运行：
  捕获停止，打印摘要，如果你要求了，会写入 `--repro-out` 报告和 `--log-file`，WinDivert 驱动被卸载，
  日志写着 `Terminated (console window closed).`，退出码是 `143`。
  Windows 只会为这一清理等待大约 5 秒。注销或关机会立即结束程序。Windows 仍会关闭它的捕获，
  所以不会有流量继续受到影响，但注销之后，驱动可能一直保持加载，直到执行 `--cleanup-driver` 或重启。
- **没有流量 = 一次绿色的运行。** 如果过滤器一个数据包都没捕获到，程序工作正常，退出码为 `0`。
  想让它成为错误 -> `--fail-on-no-traffic`。
- **流量过滤器和运行时长只在开始时生效**（和图形界面一样）：“应用更改”不会改动它们。
- **停止之后，延迟队列中等待的数据包会被丢弃。** 在 `--latency 5000` 时，这可能是一次丢掉相当多的数据包，
  这不是泄漏，而是会话的结束。
- **限速带有缓冲区（`--buffer`，默认 1000 ms）。** 当提供的负载超过限速时，缓冲区一旦填满，
  多余的部分就计入“因限速丢弃”（一个单独的计数器），这是链路堵塞时的行为，不是 bug。
  在会话中途提高限速，要等缓冲区排空之后才生效（最多约 `--buffer` ms）。想要旧的无界缓冲区
  （数据包不被丢弃，代价是延迟不断增长）？请设置 `--buffer 0`。
- **`--dst-port "!53"` 也会覆盖没有端口的流量**（例如 ICMP）：没有端口的数据包“不是端口 53”。
- **单独的进程名是子串**：`--target chrome` 也会捕获 `chromedriver.exe`。
  要精确：`--target "re:^chrome\.exe$"`。
- **范围两端都包含在内**（`80-80` = 一个端口），与 nmap/iptables 一样。
- **CLI 始终是英语**，与图形界面和系统语言无关。
- **`-q` 真的很安静**：成功时它什么也不打印。请从退出码读取结果（或加上 `--format json`）。
- **不带管理员权限运行**（并且不带 `--simulate`）会以代码 `7` 结束，而不是“毫无声响”。
- **驱动锁住了 `%TEMP%` 里的文件？** 那是旧版 onefile 构建留下的遗迹：
  `BeanNetworkTester.exe --cleanup-driver` 无需重启系统即可释放它。

**有三项静态检查与测试并行运行**，仅在 Linux 上，因为它们读取源码而不是运行源码。
**ruff** 在发现无用代码或典型 bug 形态（`F` 和 `B`）时让拉取请求失败，
并把安全类（`S`、`ASYNC`）作为从不阻断的注解报告。它的两条规则是上限而不是意见：
`C90` 限制穿过一个函数的路径有多少条，`PLR0913` 限制它接受多少个参数，
两者都设为目前存在的最宽值，所以在有东西超出它之前，它们都不会出声。
**mypy** 对整个包做类型检查。**semgrep** 使用它默认的注册表规则集扫描，
ERROR、HIGH 或 CRITICAL 级别的发现会让运行失败，低于这个级别的则完整打印。
这三个工具的版本都是固定的，所以某个 linter 的新版本不可能让一个什么也没改的拉取请求变红：
ruff 和 mypy 固定在 `requirements-lint.txt` 中，CI 按精确的文件哈希安装它，
semgrep 固定在 `requirements-scan.txt` 中，只固定到版本号。
semgrep 是唯一一个固定版本也无法保证结果稳定的地方，因为它在运行时下载规则。

**依赖项从三个方面检查。** `audit` 作业对已安装的运行时和构建依赖集运行 pip-audit。
`review new dependencies`（`.github/workflows/dependency-review.yml`）会让这样的拉取请求失败：
它新增了有已知公告的依赖项，或项目无法发布的许可证。
**OSV-Scanner**（`.github/workflows/osv-scanner.yml`）对照 OSV 数据库读取每一个固定的 requirements 文件：
在 `master` 上以及每周，它会向“安全”选项卡报告，而在拉取请求上，
只有当该拉取请求引入了新的公告时才会失败。

有一个步骤值得了解，因为没有任何单元测试能完成它的工作：在虚拟屏幕下，
使用真实 Tk 做的**图形界面渲染检查**，使用支持的最小分辨率 1366x768，**覆盖每一种语言**。
它构建真实的窗口，走遍每一页，打开“关于”窗口，并在任何按钮比它自己要求的更窄，
也就是文字被裁掉时让构建失败。波兰语的标签比英语的更长，所以那里是布局最容易出问题的地方，
它也发现过在英语中看不出来的问题。

发布通过第二个工作流（`.github/workflows/release.yml`）在 `v*` 标签上进行。
它会对照 `VERSION.txt` 检查标签，在变更日志仍处于未结束状态时拒绝发布，
构建并对 exe 做冒烟测试，然后创建一个带有 SPDX SBOM 的**草稿**。
它特意不发布任何压缩包：签名密钥存放在任何运行器都够不到的硬件卡上，
所以压缩包是在维护者的机器上签名（`tools/sign_release.py`）并从那里上传的，
随后由第三个工作流为实际发布的字节出具证明。

因此，一个已发布的版本包含 zip、本 README 让你去校验的 `SHA256SUMS.txt`、SBOM，以及证明包。
正式版还有第五个文件，即 `.msi` 安装程序。候选版没有，因为 Windows Installer 会忽略 `-rc.1`，
会把候选版和它的正式版当成同一个版本。

## 工作原理（简述）

核心 `BeanCore.decide()` 是一个纯函数，它按以下顺序决定一个数据包的命运：
目标定位 -> 局域网模式 -> 阻断（防火墙）-> NAT -> RST -> 时通时断 -> MTU -> SYN -> 丢包 -> 数据损坏 ->
延迟/抖动/尖峰 -> 吞吐量限制（带有界缓冲区的令牌桶，可以选择来自计划）-> 重复。
捕获线程读取数据包并运行决策，重新注入线程在选定的时刻把它们发送出去。
所有随机性都经过同一个生成器（可以选择指定种子）。

## 说明与限制

- 它会修改匹配过滤器的流量。要做范围更窄的测试，请使用“目标进程”或“目标地址筛选”。
- Ping = ICMP：要影响它，请选择包含 ICMP 的过滤器。
- 限速在 ping 上很难看出来（小数据包），请用文件下载来测试。
- 真正的 RST 捕获和注入只能在装有 WinDivert 的 Windows 上进行。其逻辑由随处都能运行的测试确认。
- 这是一款用于测试你自己的应用和网络的工具。

### 值得了解的行为

- **计划会循环**：最后一步之后会回到第一步（`2:100:0, 2:500:0` 会无休止地交替 2 秒 100 KB/s 和 2 秒 500 KB/s）。
  会话中途应用一个有变化的计划，会让循环从第一步重新开始。再次应用同一个计划，或者更改任何其他设置，
  则让循环保持在原处。
- **计划优先于固定限速**：当“计划”字段非空时，“下载/上传”（KB/s）的值会被忽略，因为吞吐量来自计划的步骤。
- **计划是可选的，但必须有效**：空字段 = 没有计划，而错误的条目
  （例如 `1:100`、`2:abc:0`）会被报告为错误：图形界面不会开始会话，CLI 会以一条消息结束。
  不会有任何东西被悄悄跳过。
- **过滤表达式会被校验**：进程/IP/端口字段中的无效条目（例如
  `999.1.1.1`、`2000-1000`、`>chrome`、`re:[`）会被报告为错误，而不是悄悄地什么也不做：
  在图形界面中，字段变红，原因显示在下方，CLI 则以一条 `error: ...` 消息结束。地址比较与写法无关
  （IPv6 的简写形式和完整形式是同一个地址）。
- **正向项相加，排除项相减**：`80,443,!8080` 的意思是“80 或 443，但不含 8080”，
  单独的 `!53` 则表示“除 53 以外的全部”。各项的顺序无关紧要。细节和边界情况：
  [过滤语法](#过滤语法进程--ip--端口)。
- **范围两端都包含在内**：`8000-8100` 涵盖 8000 和 8100（与 nmap/iptables 一样），
  而 `80-80` 恰好是一个端口。
- **“目标地址筛选”中的 IP 和端口以 AND 组合**：同时设置两个字段，会把范围缩小到
  **同时**满足两个条件的流量。
- **非常低的限速 = 真实的丢包**：在默认缓冲区（1000 ms）下，缓冲区一旦填满，高出限速的部分就会被丢弃，
  并计入“**因限速丢弃**”统计（一个单独的计数器，不是“丢包”）。拥塞的链路就是这样表现的，
  所以有效丢失率可能高于设定的“丢包”百分比。只有在 `--buffer 0`（无界缓冲区）下，
  工具的队列才会增长到 **20 000** 个数据包的硬性上限，之后多余的部分计入“**缓冲区溢出**”。
- **随机种子字段为空 = 随机种子**：程序仍会抽取一个具体的值，并显示在会话面板中。
  在配置文件中，值 `-1` 表示“随机化”，所以 `-1` 不能用作普通的种子
  （其他任何数字，包括负数，都能正常使用）。
- **进程定位包含子进程**：如果打开某个套接字的进程**或它的任何祖先进程**匹配，该套接字就属于目标。
  这就是为什么 `chrome.exe`（或浏览器窗口的 PID）也能捕获它的网络进程，那才是持有全部连接的进程。
  明确的排除项优先：`chrome, !chromedriver` 不会通过父进程把 `chromedriver` 拉进来。
- **进程定位由套接字事件驱动，而不是缓慢的轮询。** WinDivert 交给我们的是数据包，而不是 PID，
  所以我们按**本地端口**把数据包映射到它的进程。在 Windows 上，工具会实时监视系统的套接字事件
  （connect / bind / accept / close），因此一个**已经**在范围内的程序，其新的连接**或 UDP 流**
  从第一个数据包起就会受到影响，DNS 查询和 QUIC 也在其内，它们每次都会使用新的端口。
  例外是程序的*第一条*连接：在它至少拥有一个套接字之前，没有任何东西可以用来识别它，
  所以那一条连接会不受影响地通过。没有真正的 WinDivert 时（测试/模拟路径），会退回到每秒数次扫描套接字表，
  此时任何全新连接的第一个数据包都可能溜过去。不管哪种方式，监视都运行在它自己的线程上，
  从不占用处理你数据包的线程，所以它绝不可能变成丢失的流量。
- **如果被测程序重启，请按名称瞄准，而不是按进程 ID。** 实测：退出后以新的进程 ID 回来的目标，
  会被自动重新识别，而重启恰好损失一条连接，也就是它在拥有任何套接字之前打开的那一条。
  瞄准**进程 ID** 则永远无法恢复，因为该 ID 指的是已经退出的那个进程：重启之后的一切都不受影响。
  Windows 之后把同一个编号分配给的另一个程序也同样不受影响：进程 ID 永远只表示你设定目标时拥有它的那个进程。
  在命令行中，发生这种情况时运行会提示，并在结束时给出所捕获流量中实际处于范围内的比例。
  在窗口中，它是进程字段下方的红色提示。
- **单独的排除项也会覆盖工具无法识别的一切。** 进程字段中的 `!chrome` 表示“对除 chrome 之外的一切施加影响”，
  而“一切”包括任何无法确定所属进程的连接：工具无法打开的受保护系统进程，
  以及在轮询后备方式下，全新套接字的最初几个数据包。
  **所以不要用排除项来保护某个应用。** 如果你想放过某个应用，请写出你确实想弄坏的那个应用（`--target thatapp`），
  这样任何无法识别的东西都会不受影响地通过，这才是安全的方向。这与下面端口上的 `!53` 相呼应。
- **什么也没捕获到的定位什么也不会破坏**：如果没有任何匹配的进程打开了连接，流量就会不受影响地通过。
  这包括没在运行的程序，以及在运行但处于空闲状态的程序。当这样的程序打开一条连接时，
  工具会在几毫秒内把它加入，所以这条连接最初的几个数据包可能不受影响地通过，其余的则受到影响。
  程序会明确说明这一点（字段下方的红色提示和一条日志），因为“什么也没有坏的一次运行”
  看上去与“应用扛住了”毫无区别。
- **单独的进程名是子串**：`chrome` 也会捕获 `chromedriver.exe`。这是有意保留的
  （为了兼容旧的配置）。要精确，请使用 `re:^chrome\.exe$` 或排除项 `chrome, !chromedriver`。
- **指明了所有程序的目标什么范围也没缩小**：`*.exe`、`exe` 或 `*` 几乎匹配每一个有连接的进程，
  所以这样的运行会得到与完全没有目标的运行相同的开始时警告。
- **统计和连接默认显示所有捕获到的流量**：即“要修改的流量”过滤器放行的一切。
  定位（进程 / IP / 端口）只决定**什么会被破坏**，而不决定表格和计数器中能看到什么。
  “设置”中的“**范围**”卡片里有两个开关可以改变这一点，而且它们不是一回事：
  - “**仅显示目标流量**”会把计数器、吞吐量图表、连接表和连接 CSV 收窄到你的定位所选中的内容。
    它改变的是你所**看到**的内容：绝不改变捕获了什么，也绝不改变哪些受到影响，而且你可以随时切换。
  - “**仅捕获目标流量**”收窄的是*捕获本身*：驱动不再交出目标地址之外的任何流量，
    所以各个选项卡涵盖的就是那些流量，因为再没有别的可涵盖。它在会话开始时固定下来，
    而且只对驱动的过滤语言能表达的目标地址有效：单个地址、列表、范围或 CIDR。
    通配符、`re:` 模式或只针对进程的定位无法下推，此时该选项不起作用。“范围”卡片会在你按下
    **开始之前**说明你得到的是两者中的哪一个，日志在开始时会再说一遍，
    而会话面板中的“**捕获范围**”一行会为这次运行记录下来。

  无论开启哪一个，**计数器上方和连接表上方的提示都会说明这些数字实际涵盖什么**，
  也包括捕获被收窄*并且*设置了进程目标的情形：此时工具会捕获来自每个进程的、你目标地址的流量，
  而只对其中一个进程的那一份施加影响，所以计数器涵盖的范围比弱网影响更大。
  **即使开启了“仅显示”，仍有三个计数器保持统计全部流量**：“缓冲区溢出”“停止时丢弃”和“发送失败”
  统计的是*本工具*丢失的数据包，包括你从未指定为目标的流量，隐藏它们就等于隐藏了工具自己造成的损害。
  统计 CSV 同样不遵循“仅显示”开关（它是一份追加日志，所以把两种合计放在不同的列里），
  但它确实会在每一行的 `capture_narrowed` 中记录“仅捕获”，因为这一项改变了统计的内容本身。
  复现报告和 `--format json` 始终包含两组数字。
- **限速塑造的是平均值**：令牌桶允许短暂的突发通过，所以“下载/上传峰值”（以 1 秒窗口取平均）
  可能比设定的限速略高一点。重复的数据包会计入限速（第二份副本也要在链路上传输）。
- **窗口有最大尺寸，且不能最大化**：这种布局（两列 + 日志栏）拉伸到 4K 就没有意义了，
  所以尺寸有上限，最大化按钮也被移除。
- **运行时长从开始起计算**：会话中途更改这个字段不起作用（和流量过滤器一样）。
  达到时限后，程序只是停止，并把结果留在屏幕上。
- **停止会丢弃延迟队列中等待的数据包**：会话的结束是即时的。在较大的 `latency` 下，
  这表现为一次性的“空档”，不是 bug。
- **会话中途的故障总是以恢复网络收场**：如果捕获线程或注入线程死亡，或者 10 秒没有任何进展，
  引擎会自行停止并释放驱动（*fail-open*），而不是持有一个没人能够到的打开句柄
  （这曾是“用户突然没有互联网了”的一个真实成因）。原因会写入日志和事件日志。
  停止之后仍然卡住的线程会被撇在一边，而不是等待它，下一次开始时日志会说明这一点。
- **关闭程序会释放 WinDivert 驱动**：不是在每次会话之后（会话重新开始应当是即时的），而是**退出时一次**。
  只要驱动还处于加载状态，内核就会一直打开 exe 旁边的 `WinDivert64.sys`，于是
  **程序目录无法删除，即使它看上去是空的**（Windows 允许你删除一个有打开句柄的文件：
  它会从列表中消失，却停留在*待删除*状态，并阻止删除目录）。如果有东西残留，
  无需重启的补救办法是 `BeanNetworkTester.exe --cleanup-driver`（或 `sc stop
  WinDivert` + `sc delete WinDivert`）。退出时，程序只会动它自己加载的 `WinDivert` 服务，
  并且在本程序的另一个副本正在使用它时，让它保持加载状态。`--cleanup-driver`
  还会停止 `WinDivert1.4` 和 `WinDivert1.1`，那是其他程序安装的。
- **“运行时长”和“要修改的流量”只在开始时采纳**：这就是为什么在会话期间两者都是**锁定**的
  （一个可编辑却什么也不做的字段，比一个变灰的字段更糟）。

## 关于 SmartScreen 与杀毒软件的说明

**从 0.5.0 起，.exe 已签名**，所用证书的私钥存放在一张从不离开维护者办公桌的硬件卡上，
所以 Windows 会显示发布者的名称，而不是“未知发布者”。请了解这能带来什么、不能带来什么：
新证书还没有 SmartScreen 信誉，所以警告仍可能在一段时间内出现，
有些杀毒软件对一个要求管理员权限并加载网络驱动的程序，可能仍会误报。
变化在于，警告现在会说明是谁签的名。**WinDivert 驱动本身由其作者进行了数字签名**。
你仍然可以对照发布版本的 SHA-256 校验和（`SHA256SUMS.txt`）来确认文件在传输中没有变化。

**你还可以检查下载内容里有什么，而不仅仅是它没有变化。** 每个发布的压缩包都附带一份已签名的声明，
列出其中的所有内容，由本仓库自己的工作流针对你所下载的这些确切字节出具：

```bash
gh attestation verify BeanNetworkTester-v0.5.0-windows-x64.zip -R donislawdev/BeanNetworkTester --predicate-type https://spdx.dev/Document/v2.3
```

校验和证明文件与发布页面上所写的一致。而这条命令证明的是，它旁边的物料清单描述的正是这些字节，
并且这份声明是由本仓库中的某个工作流出具的，而不是由递给你文件的随便什么人出具的。

`--predicate-type` 不是可选的。没有它，`gh` 会去找构建来源声明，并返回 `HTTP 404`，
因为你下载的压缩包是**在维护者的机器上签名**的，而不是在运行器上构建的：签名密钥在任何运行器都够不到的卡上。
来源证明针对的是工作流中未签名的构建。随发布版本一同提供的，是针对已签名文件的物料清单。

那条命令向 GitHub 询问存在哪些证明。这份证据也**以文件形式**提供，
即 `BeanNetworkTester-vX.Y.Z.sigstore.json`，这样你就可以对照随压缩包一起传来的证据来检查它：

```bash
gh attestation verify BeanNetworkTester-v0.5.0-windows-x64.zip --bundle BeanNetworkTester-v0.5.0.sigstore.json --repo donislawdev/BeanNetworkTester --predicate-type https://spdx.dev/Document/v2.3
```

两个额外的参数都需要，没有一个是摆设。`--repo` 指明签名身份必须匹配的仓库。
`--predicate-type` 之所以需要，是因为这个证明包是 **SBOM** 证明，而 `gh` 除非你另有说明，
否则会去找构建来源证明，没有它你会得到“no attestations found with predicate type”，
这是工具在精确地表达，而不是出了故障。文件没问题时，它什么也不打印，并以 0 退出。改动一个字节，它就以 1 退出。

三份声明，值得知道它们回答的是不同的问题。**签名**说明谁为这个文件担保。
**上面的证明包**把这个确切的压缩包与它的物料清单绑定在一起，它是在签名之后、针对你所下载的字节出具的。
**构建来源**说明是哪个提交和哪个工作流产出了随后被签名的构建，它必然描述的是未签名的构建，
因为签名会改变字节，而且它位于本仓库的证明存储中，而不在下载包里。

### 下载内容里有什么，以及如何验证

每个发布版本都附带一份 **SBOM**，这是一份采用标准 SPDX 格式的清单，列出构建中的每个第三方组件，
包括它的版本、许可证和源码所在位置。它与 `BeanNetworkTester.exe --license` 打印的是同一份清单，
只是形式便于工具读取。

SBOM 是**针对它所描述的压缩包签名的**，所以两者无法分开：

```bash
gh attestation verify BeanNetworkTester-vX.Y.Z-windows-x64.zip --repo donislawdev/BeanNetworkTester --predicate-type https://spdx.dev/Document/v2.3
```

校验和告诉你文件在传输中没有变化。证明则告诉你，*这份*物料清单属于*这个*压缩包，
并且这份声明是由本仓库的发布工作流出具的。省略 `--predicate-type` 时，`gh` 会改为去找构建来源声明，
并返回 `HTTP 404`。
